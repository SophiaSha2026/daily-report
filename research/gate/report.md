# 绝对门槛（过线就出、出了就准）研究（research/gate，2026-10-18）

（Fable 5.1 high 子代理写成，主会话落盘。条文 criteria.txt 写在任何门槛结果之前；数字见 results_table.txt / results_screen.txt / results_dev.txt / results_diag_top.csv / results_intraday.txt；逐步记录 progress.txt；每次看数记 ledger.jsonl。北京 03:40~05:10 跑完，没进 16:00~18:30；没改 src / state / data/breakout 生产文件 / out_*；2026-01..08 标签一行没读；evalkit 新族 breakout_gate 登记 5 个臂（data/breakout/raw/exp/gate_v1/prereg.json、gate_v1_f6/prereg.json）。）

用户要求（2026-10-18）：「给一个标准，过这个标准就出，不过就不出，但是出了的话就得够准。用任何可能的方法，需要数据就去深挖。」

## 一屏结论

**做不出「过线就出、出了就准」的门槛：没有任何一个量，在只用之前数据定线的读法下，出的票能稳定达到 20% 以上的精确率。** 最好的诚实结果仍是 ret20 名次本身（第 1 名 筛选集 14.4% / 开发集 18.1%，第 1~2 名 15.0 / 19.4%），而且第 1 名的滚动 12 个月精确率在 7%~21% 之间来回漂（2023-06 7.4%，2024-08 20.2%，2025-12 21.0%），没有一个 12 个月窗口稳定在 20% 以上，所以按「过去 12 个月 >= τ」定的线，在开发集 19 个月里一次都不触发（τ = 0.20）。

- 训了模型反而更差：LightGBM / 逻辑回归用原值特征（日线 + 名次 + 市场状态 + 非价格 + deepdata 六张表），不论候选宇宙是全候选池、ret20 前 300、前 50 还是前 20，每月分数最高的 10~40 行在筛选集只有 7~12% 命中（名次第 1 名 14.4%），开发集 14~22%（名次 18.1%）；标签按天打乱再训，开发集还有 11~13%：模型在开发集的「本事」大半是挑日子，不是挑票。
- 门槛的两个坑都在数据里真实发生了：(1) 等渗校准的尾部只有几行，2024-01 微盘股崩盘时模型给 1330 只跌了 29% 的票打 p̂ 0.88（2023 年校准窗里分数到这个水平的只有 1 行），出 1330 只命中 2.9%；(2) 加了「支持数 >= 100 行且 >= 20 天」之后，筛选集整段不出票，开发集在 2024-09（候选池基准率 31%）之后校准窗被它带高，2024-10..12 每天出几十到上百只，命中 4~5%。**一个热月就能把绝对门槛带偏三个月。**
- 规则挖掘（<= 3 个条件的合取，拟合窗选、复核窗确认、测试月才用）一样：筛选集 τ=0.20 出 2.5 只/天命中 12.2%（p̂ 22%），τ=0.25 出 0.25 只/天命中 7.0%。
- 非价格数据（龙虎榜 / 两融 / 大宗 / 户数 / 调研）和 deepdata（席位战绩 / 评级 / 融券 / 申万行业 / 同花顺题材 / 业绩预告回购等事件）进模型，顶部命中不升；日内分时特征（research/intraday 12 个抽样月、前 50）配对检查：按天 AUC 差 −0.013 / +0.011，每天前 3~10 名命中差 ±1.7pp 内、NW t < 1.8，门槛 τ=0.20 不出票。
- 打乱标签自检：全表打乱 / 每天内打乱两版，带支持数的门槛两段都不出票；每月前 N 行命中回到候选宇宙基准（筛选集 2.6~4.3%、开发集 11~15%）。流程本身不会凭空造出精确率。
- **上线建议：不往 daily.py 加绝对门槛。** 若一定要「少出、空榜也行」，唯一站得住的是把名额从 10 缩到 1~2（= precision 报告的 B(1) / B(2)：15.0 / 19.4%，65~86% 的交易日零命中），那是「量换精度」不是「出了就准」；其区间下界（9.7 / 13.7%）不高于现行前 10 的点估计（11.3 / 16.5%）。

## 判定条文要点（criteria.txt）

- 尺子沿用 research/precision 的实现：P = Σh/Σn，按天影响函数 NW se（滞后 20）+ 块自举区间；对照同量名次基线 B(k̄) 和日配基线；两段 筛选 2022-01..2024-05（582 天）/ 开发 2024-06..2025-12（387 天）；候选池 = polish pool（elig0 + 减持 / 解禁 / 增发剔除），不限名次（4774562 行，B(10) 对账 11.34 / 16.54 逐位一致）。
- 「没碰过的」读法：逐月滚动（2021-07..2025-12），测试月 m 的模型只用 m 之前 36 个月净化过的行；门槛也只用 m 之前的数据：在 m 之前 12（或 36）个月的样本外分数上做校准（等渗 p̂(s)，或「分数 >= s 的行的累计精确率」且 >= 100 行、>= 20 天），p̂ >= τ 就出，τ = 0.20 / 0.25 / 0.30 / 0.40 / 0.50。
- 配置只在筛选集上挑；开发集每族读一次最终配置。筛选集 ΔP < 0 的臂不登记。
- 「可用」= 两段 V >= 150 且出票天 >= 60；两段 P 的块自举下界 >= 该段 B(10)；两段 ΔP 对 B(k̄) >= 0 且合并 NW t >= 2.5、块自举 p < 0.05；两段实际 P >= 0.8 τ。

## 为什么做不出来

1. 顶部信号薄、按天聚集。第 1 名命中 14~18%，滚动一年在 7~21% 漂，漂的主因是当月市场。绝对门槛要的是「这只票 >= τ」，数据里能分辨的是「这个月容不容易中」。
2. 校准只能用过去，过去的热月把线定歪。2021 下半年、2024-02、2024-09 三段热市之后，不论等渗还是累计精确率，线都被压低，随后几个月大量出票命中 3~13%。支持数 >= 100 行 / 20 天挡住了「几行外推」，挡不住「一个热月」。
3. 原值特征喂树模型，学到的是崩盘反弹。全候选池 LightGBM 顶部是 2022-04、2024-01/02/04 这些 20 日跌 25~45% 的票（2024-02 真中 44.7%，2024-01 4.9%、2024-04 1.4%），按天整体押注；限到前 300 / 50 名宇宙之后也没赢过名次（和 polish 的交叉拟合天花板一致）。
4. 非价格、席位、题材、日内数据分辨的是「11~50 名里谁像 1~3 名」，到 1~3 名没有增量（altdata / precision / intraday / deepdata 四份结论一致），进了模型抬不起顶部。

## 上线建议

- 不加门槛。现行「候选池内 ret20 前 10」照发。
- 若仍要「宁缺毋滥」：只改名额常量（CAP_A 10 → 2 或 3），不加分数线；邮件抬头印两段精确率 15.0 / 19.4%（B(2)）、65~73% 交易日零命中、筛选集 4 个整月零命中。
- 想继续做绝对门槛，要解决的不是模型，是校准的时变：要么找到两段都成立的日级量把「这个月容不容易中」提前分出来（precision / altpath 没找到），要么接受按长期平均定线（36 个月校准，开发集照样不触发）。没有新的日级信息之前，再训模型不会改变这张表。
- 每天多算的数据：无。
