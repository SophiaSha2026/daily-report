## 一屏结论

- **公式和实现都对**：P = Σh/Σn、按天影响函数 NW se（se = sqrt(D·LRV(u))/V）、块自举比值区间、B(k̄) 分数插值、ΔP 的 u 序列与 NW t、evalkit 的 NW t / 块自举 p / `_maxt_null` / 并集上界 / 去最好月 / 滚动三月 / v2 v3 判定、truth.wilson、MDE80 = (c+0.84)·se。合成数据下全部按预期工作，没有发现写错的公式或接错的线。
- **对账逐位一致**：11.34 / 16.54 / 13.42、7.58 / 12.64 / 9.60、15.19 / 9.31、1.62 / 4.32 / 2.60、B(1) 14.4 / 18.1、B(2) 15.0 / 19.4、三句事实 100 / 19.6 / 15.2 / 2.6 / −7.6 / −1.8 / −19.9 / 50、登记簿 diff 序列逐日 0 差、按天差 +3.76 (4.14) / +3.90 (2.41) / 合并 4.50、块自举区间 [8.6,19.8] 等；export.RULE_PERF / RULE_FACTS 与 rulecore report 第 0 / 8 节完全一致。
- **蒙特卡洛覆盖率**：独立 / AR(1) 日级相关下 NW 正态区间和块自举区间覆盖 0.91~0.96（名义 0.95，合格）。**按天聚集 + 20 天标签重叠**下（和生产同形态，设计效应 8）两者只有 **0.87~0.91**：Bartlett 滞后 20 / 块长 20 刚好等于依赖长度，理论上只抓到 MA(19) 长期方差的 68%（se 低估 17%）。真实序列的自相关衰减更快，实测 se 低估约 8~15%（L=20 对 L=40/60）。
- **最严重的 3 个问题**（都是「偏乐观的尺度」，没有一个翻转已有判定）：
  1. NW 滞后 20 / 块长 20 偏短：重叠结构下 NW t 的 sd 1.21~1.27（应为 1），P(NW t >= 2.5) 在 n=387 时 2.5%（名义 0.6%），块自举 p<0.05 的实际水平 9.5~13.8%；族门槛零分布用同一把 se，纠正不了这个膨胀。
  2. ltt_an「可证下界」承诺过头：k=10 时单侧 95% 下界的覆盖只有 0.90~0.93；「LTT 固定序列、族错误率 5%」不成立（五条 k 链各自独立重启）。
  3. v3 过线的实际功效低于 MDE80 的承诺：效应恰为 (2.5+0.84)·se 时 t 条件单独 80%，加上块自举 + 去最好月后只有 63~65%（n=969）。

## 问题清单（按严重程度）

**P1 NW 滞后 20 / 块长 20 偏短，所有「按天」推断的尺度偏乐观 8~20%**
- 现象：标签窗口 20 根 ⇒ 相邻天的序列相关到滞后 19；Bartlett(L=20) 对 MA(19) 等权相关只抓到 68% 的长期方差（L=30 79%、L=40 84%、L=60 89%）。真实序列自相关衰减更快（ret20−base 的 ACF 0.44, 0.27, 0.23, 0.19, 0.13，滞后 20 处 ≈ 0），按天差序列 L=20→L=40 se 涨 3~10%，单臂命中序列和 B(10) 涨 12~15%。
- 影响范围：evalkit.compare（t_nw、boot、_maxt_null 族门槛）、common_pr.evaluate、ltt_an 下界、precision 功效表、hac.py。
- 受影响的已有数（L=40 / 块 40 重算）：rulecore ret20−base 合并 NW t 4.50 → 4.16（L=60 3.98），筛选 4.14 → 4.00，开发 2.41 → 2.17；rc 2.24 → 1.98；pc 1.76 → 1.73；确认集 2.17 → 2.22、块自举 p 0.039 → 0.017；B(2)−B(10) 不变；单侧 5% 下界 筛选 B(1) 9.3 → 8.2、B(2) 10.4 → 9.5、B(10) 9.5 → 9.0，开发 B(1) 11.4 → 10.6、B(2) 14.5 → 14.3、B(10) 13.3 → 13.0。**没有一个判定翻转**。
- 修复建议：NW 滞后和块长改为 2× 标签窗口（L=40、块 40），或 Andrews 规则并钉住下限 40；`t_nw_lags` 加 40/60 并印在 fmt_compare；selftest 用 MA(19) 合成序列钉住「NW se / 真 se >= 0.9」。

**P2 ltt_an「可证下界」偏高，LTT 族错误率的说法不成立**
- k=10 时单侧 95% 下界实际覆盖 0.90~0.93；五条 k 链各自重启，不是一条固定序列。结果偏高约 0.5~1pp，只是描述性结论。
- 建议：块长同 P1；去掉「族错误率 5%」的措辞，或真按单一序列排。

**P3 v3 过线的实际功效低于功效表承诺**
- 效应恰为 MDE80 时整套条文通过率约 65%（n=969）、79~84%（n=582/387）；「要高 8pp 以上才有 80% 功效」实际要 9~10pp。没改变「0 个臂过线」。
- 建议：功效表按整套条文的通过率定 MDE，或把 MDE80 的 c 改成 2.5·1.15。

**P4 族门槛 FWER 略超 5%**（0.05~0.09）
- 原因：NW t 尾比正态胖，Bonferroni 那部分按正态尾算；P1 的重叠结构会更大。
- 建议：无序列试验按 t(n_eff) 尾；或 Bonferroni 项乘 1.3。

**P5 口径小不一致（无可见影响，但是教训 34 的形态）**
- learn._validation：hit 买得到（13.8%）配 base 收盘口径（2.93%），该用 base_open（2.89%）。
- learn._live / truth._breakdowns / by.all：收盘口径 hit，邮件成绩常量是买得到口径；truth 已算了 hits_open / base_open_final，卡片该印那组。
- truth.paired：se 用 iid（std/√n），和 evalkit 的 NW 不是一把尺子；影子配对满 20 天后 t 会偏大约 1.5 倍。建议调 evalkit 的 NW（天数 >= 23 才算）。
- 候选池基准是按天均值再平均，前 10 命中是池化；差 0.03~0.05pp，建议表头注明或统一。
- export.py 第 315 行注释、validate.py 第 254 行注释仍写「BASE=2.93%」（收盘口径旧值），现 BASE=2.89 买得到口径。

**P6 math_an 的读法有两处过头**
- 「实测第 1 名 14~18% 对应 AUC 0.70~0.75」应为 0.65~0.68。
- 「>=30% 基本不可达」依赖等方差双正态；ret20 第 1 名 14.4%（π 1.6%）已高于等方差 AUC 0.65 的 12.4%，说明真实右尾比等方差双正态厚，这张表不能当上限用。

**没有问题的**：公式和接线无错；B(k̄) 插值、ΔP 的 u 序列和 NW t 的等价、块自举重采样单位、`_maxt_null` 的缺值处理、并集上界求解、v2/v3 路由、Wilson、MDE80 公式、对账全部数字、export / learn 的来源链路都对得上。
