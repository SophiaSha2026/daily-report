# 爆发线（breakout）设计

> 状态：**设计稿，待批准**。2026-09-12 起草。
> 定位：替代已停用的形态线 17:00 报告，成为项目第三条流水线。
> 目标：每交易日 17:00 出两个清单。
> A = 技术上接近起涨（历史经验：5 个交易日内启动，一个月涨超 50%）。
> B = 曾在 A 上得过 90 分以上、现在出现波段见顶特征的票。

本文档的第 2 节是**反对意见**，请先读。它决定这套东西值不值得做，
以及做出来能信到什么程度。

---

## 1. 数据可得性（2026-09-12 本机实测）

全部结论来自实测，不是推断。数据源可达性会漂（CLAUDE.md 教训 6），
每条都标了日期，实施时要重测。

| 数据 | 源 | 历史深度 | 全市场耗时 | 结论 |
|---|---|---|---|---|
| 日线 OHLCV | 腾讯 `web.ifzq.gtimg.cn` | **800 根 = 3.28 年** | 30 分钟（5 并发，329ms/只） | ✅ 主力 |
| 当日换手率/成交额/流通市值 | 腾讯快照 index 37/38/44 | 仅当日 | 3.6 秒 | ✅ |
| ST 标记 | 腾讯快照名称字段 | 仅当日 | 含在快照里 | ✅ |
| 解禁明细 | 东财 `datacenter-web` | 按日期区间查 | 秒级 | ✅ |
| 高管/股东减持 | 巨潮 `stock_hold_change_cninfo` | 全市场 5640 行 | 3.7 秒 | ✅ |
| 资金流（主力/超大单） | 东财 `push2` fflow | **仅当日 1 天** | 需逐只 | ⚠️ 见下 |
| 筹码集中度 | 东财 `push2his` cyq | — | — | ❌ 拿不到 |

### 1.1 五个板块全覆盖

代码表 5548 只：主板沪 1699、主板深 1494、创业板 1403、科创板 614、北交所 338。
随机抽样 40 只（每板块 8 只）**全部拉到**日线，北交所和科创板都正常。

### 1.2 两个拿不到的东西

**筹码集中度：拿不到。** `ak.stock_cyq_em` 内部走的是
`push2his.eastmoney.com/api/qt/stock/kline/get`，这个路径从本机三次重试全部
`ConnectionError`。同一主机的 `cyq/get` 路径能返回 404（说明 TCP 通），
所以东财是**按接口路径**限流而不是按主机 —— 别指望换个 UA 或者重试能绕过去。

代替方案是用日线构造代理指标（见 4.3 的 `cost_disp`、`vwap_dev`），
但必须说清楚：**代理不是筹码分布**，它衡量的是成交成本的离散程度，
不是持仓成本的分布。二者相关但不等价。

**资金流：只有当天。** `lmt=100` 和 `lmt=1000` 都只返回 1 行。
这造成一个根本性不对称：

> 回溯时拿不到的特征，不能进模型。

因为模型要在历史样本上训练和验证，一个只有实时值的特征既无法参与特征提取，
也无法回测。所以资金流**第一版不进模型**，改为从上线第一天起每日采集入库
（`data/breakout/fflow_<date>.parquet`），攒够样本后作为候选特征走学习线的
闸门验证。这恰好落在用户要求的「不断验证加以修正」里。

### 1.3 换手率的历史值也拿不到

腾讯日 K 只有 6 个字段：日期/开/收/高/低/**成交量**。没有成交额，没有换手率。

项目现有的反推法（`历史换手率 = 今日换手率 × 历史成交量/今日成交量`，
见 CLAUDE.md 形态线一节）只在 7 个交易日内成立，**三年尺度上不成立**：
增发、解禁、回购会让流通股本变化几十个百分点。

所以本线不用换手率，改用 **`vol_ratio_n` = 当日成交量 / 过去 n 日均量**。
它只需要成交量，完全可得，且对「突然放量」这件事的表达力和换手率相当
（换手率 = 成交量/流通股本，在短窗口内分母是常数，两者只差一个缩放）。

成交额用 `成交量 × 当日均价` 估算（均价取 `(高+低+收)/3`），误差 1~2%。

## 2. 反对意见：这套东西最可能怎么骗人

按严重程度排序。每一条都给了应对，但**应对不等于解决**。

### 2.1 事件在时间上极度聚集（最严重）

200 只随机股票、765 个交易日的抽样实测：

```
144,740 个 (股,日) 对
其中未来 20 日内最高价涨超 50% 的：4,892 个  →  正样本率 3.38%
三年内至少出现过一次的股票：157/189 = 83%
```

事件的月份分布，前 8 名：

```
2024-09: 1218   ← 单月占全部事件的 25%
2025-12:  317
2024-10:  298
2024-11:  232
2026-04:  218
2024-02:  200
```

**2024 年 9 月一个月贡献了四分之一的正样本。** 那是 924 行情，
全市场无差别普涨，当时几乎任何特征都能"预测"成功。

在这种样本上直接训练，得到的是一个**牛市探测器**，不是选股器。它会在
回测里表现惊艳，在平盘市里一只都选不对 —— 而平盘市是绝大多数日子。

应对（三条都要做，缺一条结论就不可信）：

1. **按月分层的走向前验证**，报告每个月单独的命中率，而不是只看总平均。
   一个只在 2024-09 和 2025-12 有效的模型，要能被一眼看出来。
2. **市场状态中性化**：特征里加入当日全市场涨跌分布的分位数，让模型区分
   「这只票强」和「今天所有票都强」。
3. **同时记录绝对口径和超额口径**的标签。用户的定义是绝对 50%，模型按绝对
   口径训练（尊重定义），但评估时**必须**同时报超额口径的命中率。
   如果两者差距巨大，说明模型学到的是大盘不是个股。

### 2.2 基础比率 3.38%，别被"高命中率"骗了

随机瞎猜的命中率就是 3.38%。所以：

- 「命中率 20%」听起来一般，其实是 **6 倍**基础比率，是很好的结果。
- 「命中率 60%」几乎一定是前视偏差或过拟合，不是模型强。

**验收标准（提前定死，在 holdout 上验收）**：

| 指标 | 及格线 | 说明 |
|---|---|---|
| 清单 A 前 10 只的命中率（holdout） | ≥ 15% | 4.4 倍基础比率 |
| 剔除 2024-09 / 2025-12 后 | ≥ 10% | 证明不是只会认牛市 |
| 超额口径命中率 / 绝对口径命中率 | ≥ 0.5 | 证明学的是个股不是大盘 |
| 命中率为 0 的月份 | ≤ 1 个 | 不能整月颗粒无收 |
| 最强板块 / 最弱板块 的命中率之比 | ≤ 3 | 防止只会选北交所 |

不达标时的**分级响应**（按顺序走，不许跳步，也不许反复回头微调）：

```
1. 加特征        ← 先怀疑信息不够，而不是模型不够强
2. 换模型        ← 擂台里换一层（L0→L1→L2）
3. 改事件定义    ← 例如窗口 20 日改 30 日、阈值 50% 改 40%
4. 判定不可行    ← 三步走完仍不达标，把报告交给用户决定
```

**不允许做的事**：在验证集上反复微调超参数直到达标。那不是改进，是把验证集
变成第二个训练集。每一级响应只测一次，结果记入 `docs/breakout_log.md`，
包括失败的尝试 —— 失败记录是防止将来重复踩坑的唯一手段。

### 2.3 前视偏差

这是量化里最容易犯、后果最严重的错。具体到本线有四个入口：

1. 特征用了 t 日之后的数据（例如用整段数据算均值再标准化）。
   → 所有滚动统计必须用 `shift(1)` 后的窗口，标准化参数只能来自训练集。
2. 用「已知它涨了 50%」去挑样本，再从中找特征。
   → 标签只能来自 t+1..t+20，特征只能来自 ..t。代码层面用两个独立函数，
   各自只接收允许的切片，不共享 DataFrame。
3. 复权价的未来信息。前复权序列在每次除权时会重算**全部历史价格**，
   今天拉的 qfq 序列和三年前当时看到的不是一回事。
   → 涨跌幅用复权序列算（正确），但绝对价位阈值不要用。
4. 代码表的**幸存者偏差**：`cache/codes.csv` 是当前在市的 5548 只，
   三年内退市的票不在里面。这会**高估**正样本率（退市股通常是跌的）。
   → 影响方向已知且对"找起涨特征"偏小，但要在报告里写明，不要假装没有。

### 2.4 清单 B 的样本量会很小

清单 B 的条件是「**曾在 A 上得过 90 分以上**」且「出现见顶特征」。
如果 A 每天只有几只上 90 分，B 的池子会长期是空的，模型也没样本可训。

应对：见顶模型**独立训练**，样本取自所有真实发生过的波段（涨超 50% 后
从最高点回撤 20%），而不是只取"曾上过清单 A"的票。清单 A 的 90 分只作为
**输出时的过滤条件**，不作为训练时的样本条件。这样样本量够，逻辑也对。

### 2.5 「一个月涨 50%」在不同板块不是一回事

主板日涨停 10%，创业板/科创板 20%，北交所 30%。同样是一个月涨 50%，
主板需要连续多日强势，北交所两个涨停就够了。

应对：特征里带板块 one-hot，并且**分板块报告命中率**。如果模型选出来的
全是北交所，那不是模型好，是标签定义对北交所宽松。

## 3. 事件定义

### 3.1 起涨事件（清单 A 的标签）

```
在 t 日，若 max(high[t+1 .. t+20]) / close[t] - 1 > 0.50，则 y_up[t] = 1
```

- 窗口 20 个交易日 ≈ 一个自然月
- 用 t 日**收盘价**作基准（收盘后跑，t 日收盘价是已知的）
- 用未来最高价而不是收盘价：用户说的是"上涨超过 50%"，触及即算

同时记录**超额口径** `y_up_ex`：同一算法，但收益减去同期中证全指涨幅。
仅用于评估，不用于训练（尊重用户的绝对口径定义）。

用户要求的是"上涨前 5 个交易日的特征"。注意上式定义的是**每一个** t，
而真实起涨点只有一个。所以另外定义：

```
起涨点 t0 = 一段满足条件的连续区间里的第一天
前 5 日窗口 = [t0-4 .. t0]
```

特征在 `[t0-4 .. t0]` 这 5 天上聚合（见 4.2）。训练时正样本取 t0，
负样本从非 t0 的日子里**按月分层抽样**，保持每月正负比一致
（否则 2024-09 会淹没一切，见 2.1）。

### 3.2 见顶事件（清单 B 的标签）

```
对每一段起涨波段：
  peak  = 起涨后的最高价那一天
  end   = peak 之后首次出现 close < peak_high × 0.80 的那一天
  见顶前两日窗口 = [peak-1 .. peak]      ← 用户说的"结束前两个交易日"
  y_top[d] = 1  for d in 该窗口
```

注意这里的口径选择：用户说"波段结束（从最高点下跌超过 20%）前两个交易日"。
「结束」这个词有两种读法：

- **读法 A**：回撤 20% 那一天之前的两天 → 那时股价已经从高点跌下来了，
  发出信号为时已晚。
- **读法 B**：最高点那一天及前一天 → 在顶部附近发出信号，这才有用。

**本设计取读法 B**，因为读法 A 的信号没有交易价值。这是对用户原话的
一处主动解释，需要确认（见第 9 节问题 3）。

## 4. 特征集

全部特征只用 `..t` 的数据。分四组。

### 4.1 趋势与均线

| 特征 | 定义 |
|---|---|
| `ma5/10/20/60` | 收盘价 N 日均线 |
| `ma_bias_N` | `close/maN - 1`，乖离率 |
| `ma_align` | 多头排列强度：`(ma5>ma10) + (ma10>ma20) + (ma20>ma60)`，0~3 |
| `ma20_slope` | ma20 的 5 日斜率，按价格归一 |
| `above_ma60_days` | 连续站上 ma60 的天数 |
| `dist_52w_high` | `close / 过去 250 日最高价 - 1` |
| `dist_52w_low` | `close / 过去 250 日最低价 - 1` |

### 4.2 量能（替代换手率，见 1.3）

| 特征 | 定义 |
|---|---|
| `vol_ratio_5/10/20` | 当日量 / 过去 N 日均量 |
| `vol_trend_5` | 近 5 日量的线性斜率 / 均量 |
| `vol_std_20` | 20 日量的变异系数，衡量放量是否突兀 |
| `amt_est` | `量 × (高+低+收)/3`，成交额估算 |
| `amt_pct_mkt` | 该股成交额占当日全市场的分位数 |

5 日窗口聚合方式：每个特征在 `[t0-4..t0]` 上取
**最后值、均值、最大值、斜率**四个统计量。5 天 × 若干基础特征
展开后约 120 维，后续用 L1 和闸门筛。

### 4.3 波动与成本分布（筹码集中度的代理）

| 特征 | 定义 | 代理的是什么 |
|---|---|---|
| `atr14_pct` | ATR14 / 收盘价 | 波动水平 |
| `range_compress` | 近 5 日振幅均值 / 近 20 日振幅均值 | **缩量横盘**，突破前的典型形态 |
| `cost_disp` | 近 60 日成交量加权价的标准差 / 均值 | 成交成本离散度 ← 筹码分散/集中的代理 |
| `vwap_dev` | `close / 近 60 日 VWAP - 1` | 相对平均成本的位置，套牢盘压力 |
| `up_days_20` | 近 20 日阳线占比 | |
| `max_dd_60` | 近 60 日最大回撤 | |

**`cost_disp` 和 `vwap_dev` 不是筹码分布**，见 1.2 的说明。

### 4.4 市场状态（对抗 2.1 的聚集问题）

| 特征 | 定义 |
|---|---|
| `mkt_breadth` | 当日全市场上涨家数占比 |
| `mkt_limit_up` | 当日涨停家数 |
| `mkt_ret_5` | 中证全指近 5 日涨幅 |
| `rs_rank` | 该股近 20 日涨幅在全市场的分位数（相对强度） |
| `board` | 板块 one-hot：主板/创业板/科创板/北交所 |

这一组是**必须**的。没有它，模型无法区分「这只票强」和「今天全都强」。

## 5. 模型与验证

方针：**一切以效果为最优先。** 但在 3.38% 基础比率 + 时间极度聚集的数据上，
「效果」和「看起来有效果」的距离比模型复杂度的差距大得多。所以这一节的
结构是：模型敞开上，验证卡死。

### 5.1 数据量够不够（决定能上到哪一层）

```
样本    5548 只 × 800 天 ≈ 444 万个 (股,日) 对
正样本  3.38% ≈ 15 万个
特征    聚合口径约 120 维；序列口径 5 天 × 24 维
```

- GBDT：444 万 × 120 是**舒适区**，不是勉强
- 序列模型：15 万正样本足够训 2 层 GRU（约 10 万参数）
- 大型 Transformer：**不够**，别上。金融时序信噪比低，参数量一大就是背样本

### 5.2 模型擂台

所有模型在**同一个走向前协议**（5.4）下比，按验证集成绩选，不按先验偏好选。
项目已有这个做法（`learn/model_select.py` 的模型擂台）。

| 层 | 模型 | 输入 | 依赖 | 角色 |
|---|---|---|---|---|
| L0 | 逻辑回归 + L1 | 120 维聚合特征 | scikit-learn | **尺子**，不是备胎 |
| L1 | LightGBM | 同上 | lightgbm (~2MB) | 表格数据首选 |
| L2 | GRU / TCN | 5×24 原始序列 | torch CPU (~200MB) | 学形态而非统计量 |
| L3 | L1 + L2 概率加权 | | | 仅当两者误差互补 |

**L0 的作用是尺子**：如果 LightGBM 只比逻辑回归高 1 个百分点，说明特征已经
榨干了，继续加模型复杂度只会加过拟合风险，那时该回去挖特征而不是换模型。
没有这把尺子，就无法判断"提升"来自模型还是来自过拟合。

### 5.3 为什么序列模型在这里可能真的更强

用户要的是「起涨前 **5 个交易日**的特征」。手工聚合（最后值/均值/最大/斜率）
会丢掉**次序**信息：

```
A: 缩量横盘 4 天 → 第 5 天放量突破      ← 典型启动形态
B: 第 1 天放量 → 之后 4 天缩量回落      ← 冲高回落，含义相反
```

两者的「5 日均量」「最大量」「量的斜率」可以非常接近，聚合之后几乎不可分。
序列模型直接吃 `[5 × 24]` 矩阵，能学到这种次序结构。这是 L2 存在的理由，
也是它**可能真的赢**的地方 —— 不是因为神经网络时髦。

### 5.4 增量学习

用户明确要求。神经网络天然支持，但有**灾难性遗忘**：只拿新数据继续训练，
模型会忘掉 2024-09 那类行情。而那类行情恰恰几年才来一次，忘了就白学。

```
每日   新样本进 buffer（data/breakout/feat_<date>.parquet）
每月   replay 混合训练：按月分层从历史抽样 + 当月新样本，warm-start
每季   全量重训一次，与增量版在 holdout 上对比，
       增量版落后超过 2 个百分点就用全量版替换
```

- **L2（神经网络）走真增量**：warm-start + replay buffer
- **L1（LightGBM）不走增量**：warm start 加树会让早期树的分裂点失效，
  模型漂得厉害。GBDT 每月**全量重训**，代价是几分钟，值得

### 5.5 分数刻度（0~100）

用户要求 0~100 分。直接输出校准概率会很难看（3.38% 基础比率下模型输出
大多在 2%~25%），90 分变成不可能达到的分数。

**方案**：分数 = 校准概率在训练集分布中的**百分位** × 100。
同时在面板和邮件里，每个分数段旁边印上该分段的**历史实际命中率**：

```
95~100 分   历史命中率 23.1%   （基础比率 3.38%，6.8 倍）
90~95  分   历史命中率 17.4%
80~90  分   历史命中率 11.2%
```

**这一行必须出现在每封邮件里。** 否则「90 分」会被读成「90% 会涨」，
那是在骗人。概率校准用 isotonic regression，在验证集上拟合。

### 5.6 验证协议（这一节是整个设计的地基）

```
训练集   2023-05 .. 2025-02   （21 个月）
验证集   2025-03 .. 2025-12   （10 个月，用于选模型、调超参）
holdout  2026-01 .. 2026-09   （9 个月，锁死）
```

**holdout 的规矩**：整个开发过程中**只看一次**，在模型完全定稿之后。
看完就不许再改任何东西 —— 改了它就不再是 holdout，而是第二个验证集。

理由：擂台有 4 层模型、每层若干超参，反复在验证集上比较本身就是一种
搜索，搜到最后验证集会被间接拟合（验证集泄漏）。holdout 是唯一能给出
诚实估计的东西。

其余协议：

- **走向前**：每月重拟合，只用该月之前的数据预测该月
- **分月报告**：每个月单独的命中率，2024-09 那种月份要能被一眼认出
- **分板块报告**：防止模型只会选北交所（见 2.5）
- **剔除极端月后重报**：去掉 2024-09 和 2025-12 再算一次
- **自助置信区间**：按天自助（`learn/optimize.py` 有实现可借鉴），
  给命中率的区间而不是点估计

### 5.7 风险剔除（用户明确要求）

| 剔除项 | 数据源 | 规则 |
|---|---|---|
| ST / *ST | 腾讯快照名称 | 名称含 ST |
| 近期减持 | 巨潮 `stock_hold_change_cninfo` | 公告日在近 30 个自然日内且为减持 |
| 近期解禁 | 东财 `datacenter-web` | 未来 30 自然日内解禁且市值占比 > 5% |
| 停牌 | 腾讯快照 | 当日无成交 |
| 次新股 | 日线长度 | 上市不足 60 个交易日 |

定增：公开接口里没有稳定的定增预案数据，第一版用解禁代替
（定增的实际抛压体现在解禁上）。见第 9 节问题 2。

### 5.8 依赖分线管理

CLAUDE.md 的规矩：学习线要 scikit-learn/scipy，另两条线不许沾。爆发线同理：

```
requirements-breakout.txt    lightgbm, scikit-learn, scipy
requirements-breakout-nn.txt torch (CPU)    ← 只在 L2 进擂台时才装
```

竞价线和形态线的 `requirements.txt` 不动。L2 不装也能跑，擂台自动跳过。

## 6. 每日生产

17:00 跑，收盘后数据已定死，和形态线一样"防早不防晚"（`hard_deadline` 给到 22:00）。

```
stage=scan    拉全市场日线增量 → 算特征 → 打分 → 出清单 A
              → 查见顶模型 → 出清单 B → 落 parquet
stage=send    LLM 写文案（只写 reason/risk，不参与排序）→ 面板 → 邮件
```

**清单 A 池的持久化**：清单 B 需要知道"曾经得过 90 分以上"的票。
维护 `state/breakout/a_pool.json`：

```json
{"600000": {"first": "2026-09-12", "last": "2026-09-15", "best": 94.2}}
```

有效期 **60 个交易日**，过期自动移出。这个窗口需要确认（见第 9 节问题 4）。

清单为空是正常的，必须在邮件和面板里写明，否则用户会以为流水线坏了
（形态线已有同样的教训，CLAUDE.md 里记着）。

## 7. 在线学习闭环

用户要求"不断将当天及以后出现的符合要求的个股……不断验证加以修正"。

```
每日 17:00   落当日全市场特征快照 → data/breakout/feat_<date>.parquet
每日 17:00   落当日资金流 → data/breakout/fflow_<date>.parquet（为将来接入攒样本）
每月 1 日    回看 20 个交易日前的那一天，标注实际结果，追加训练表
每月 1 日    重新拟合 → 走向前验证 → 过闸门才替换线上参数
```

闸门沿用学习线的思路（`learn/gate.py`）：新参数必须在**验证集**上不劣于旧的，
且置信区间下界仍高于基础比率，否则拒绝。参数存
`state/breakout/model.json`，`config.yaml` 永远是人工基线。

**学习系统不许改的东西**（和竞价线同构，CLAUDE.md 硬约束 8）：
剔除规则（ST/减持/解禁）是用户定的，系统只能提案。

## 8. 分阶段计划

每个阶段都有**可检验的产出**和**止损条件**。

### 阶段 0：数据层（约 1 天）

- `src/breakout/backfill.py`：全市场 800 根日线，5 并发，落
  `data/breakout/daily.parquet`（约 5548 × 800 × 6 ≈ 2700 万格，parquet 约 200MB）
- 断点续传：中途失败能接着跑，不重头来
- 产出：一张覆盖 2023-05 .. 2026-09 的日线宽表
- **止损**：若实际耗时 > 90 分钟或成功率 < 90%，改用分批缓存策略

### 阶段 1：标注 + 特征（约 1 天）

- `src/breakout/label.py`：起涨事件、见顶事件，两个独立函数，不共享切片
- `src/breakout/features.py`：4 组特征，全部 `shift(1)` 安全
- 产出：训练表 + 一份**数据体检报告**（正样本率、月度分布、板块分布、
  缺失率、幸存者偏差估计）
- **止损**：若去掉 2024-09 后正样本不足 2000 个，缩短窗口或放宽阈值重新定义事件

### 阶段 2：模型擂台 + 验证（约 3 天）⚠️ 关键关卡

- `src/breakout/model.py`：统一接口 `fit/predict_proba/save/load`，
  四层模型各自实现，擂台按同一协议比
  - L0 逻辑回归 + L1 正则（**先做，它是尺子**）
  - L1 LightGBM
  - L2 GRU/TCN（torch 装了才进擂台，没装自动跳过）
  - L3 概率加权集成（仅当 L1/L2 误差互补）
- `src/breakout/calib.py`：isotonic 概率校准 + 百分位分数映射
- `src/breakout/validate.py`：走向前、分月、分板块、自助置信区间
- 产出：擂台报告 + **holdout 只看一次**的最终成绩，直接回答 2.2 那张表
- **关卡**：按 2.2 的分级响应走。三级走完仍不达标，交给用户决定，
  不要自己决定"再试试"

### 阶段 2.5：增量学习（约 1 天，依赖阶段 2 选出 L2）

- 只有当擂台选中 L2（神经网络）时才做，否则 GBDT 走每月全量重训即可
- replay buffer + warm-start，季度全量重训对照
- 产出：增量版与全量版在 holdout 上的差距曲线

### 阶段 3：每日生产（约 1.5 天）

- `src/breakout/scan.py`：`--stage scan/send`
- `src/breakout/export.py`：面板 + 邮件，复用 `ths_export.PANEL_CSS` 和 `mailer`
- `prompts/breakout_analyst.md`：LLM 文案指令
- 风险剔除接线（ST/减持/解禁/停牌/次新）
- 产出：能跑出当日清单 A/B 的完整流程

### 阶段 4：整合（约 1 天）

- `src/selftest_breakout.py`：离线自测，重点钉**前视偏差**
  （构造一个"只有未来信息才能预测"的假数据集，模型必须学不会它）
- `local_run.py` 加 `--flow breakout`
- GUI 加按钮、面板 tab、状态卡片
- `build_site.py` 加 `out_breakout/`
- 计划任务 `DailyReport-Local-Breakout`，北京 17:00
- CLAUDE.md 补一节

### 阶段 5：在线学习（约 1 天）

- 每月重拟合 + 闸门
- 资金流样本积累
- 学习面板加爆发线的裁决时间线

**合计约 9 天工作量。阶段 2 是关卡，之前的工作在那里可能被判定为不可行。**

## 9. 需要拍板的问题

1. **holdout 纪律**：2026-01..09 这 9 个月锁死，整个开发过程只看一次，
   看完不许再改模型。这是「一切以效果为最优先」的前提 —— 没有它，
   任何命中率数字都可能是搜出来的，不是学出来的。接受吗？
2. **torch 装不装**（CPU 版约 200MB）。装了 L2 序列模型才能进擂台。
   不装也能跑，擂台自动跳过，但可能损失 5.3 说的那部分形态信息。
3. **见顶口径**：用户原话「波段结束（从最高点下跌超过 20%）前两个交易日」，
   我取的是**最高点及其前一天**（读法 B），因为等回撤 20% 再报信号已经晚了。
   确认？
4. **定增**：公开接口没有稳定的定增预案数据，第一版用解禁代替。
   接受，还是要我再找数据源？
5. **清单 A 池有效期**：暂定 60 个交易日。太长会让 B 一直挂着老票，
   太短会漏掉慢慢见顶的。
6. **时段**：爆发线要拉全市场日线（增量约 3 分钟，全量 30 分钟），
   所以 16:30 起跑、17:00 发信。占用形态线原来的位置，确认？

## 附：这套东西最终能有多大用

先把预期摆正，免得实施完了才发现和想象的不一样。

基础比率 3.38%。如果 holdout 命中率做到 15%，意味着：

```
清单 A 每天给 10 只
其中约 1.5 只会在未来 20 个交易日内涨超 50%
另外 8.5 只不会
```

这已经是**4.4 倍**于随机，是一个很好的量化结果。但它不是「选出来的票会涨」，
而是「这批票里出黑马的密度比市场高 4 倍」。清单必须按这个口径去用。

清单 B 同理：它是「见顶概率显著升高」的提示，不是「明天就跌」。

如果最终 holdout 命中率落在 5%~8%（1.5~2.4 倍基础比率），我的建议会是
**不要上线**：这个强度的信号在交易成本和情绪干扰面前会被吃掉，
而每天看一份似是而非的清单，比没有清单更糟。
