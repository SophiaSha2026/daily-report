# 爆发线（breakout）设计

> 状态：**设计稿，待批准**。2026-09-12 起草。
> 定位：替代已停用的形态线 17:00 报告，成为项目第三条流水线。
> 目标：每交易日 17:00 出两个清单。
> A = 技术上接近起涨（历史经验：5 个交易日内启动，一个月涨超 50%）。
> B = 曾在 A 上得过 90 分以上、现在出现波段见顶特征的票。

本文档的第 2 节是**反对意见**，请先读。它决定这套东西值不值得做，
以及做出来能信到什么程度。

---

## 1. 数据可得性（2026-09-12 本机实测）

全部结论来自实测，不是推断。可达性会漂（CLAUDE.md 教训 6），实施时重测。

**四个缺口经过深挖全部解决**，其中筹码集中度和历史换手率的解法是这套设计里
最关键的两个发现。

| 数据 | 源 | 历史深度 | 状态 |
|---|---|---|---|
| **日线 + 成交额 + 换手率 + 逐日流通股本** | **新浪 `stock_zh_a_daily`** | 全历史（取最近 800 根） | ✅ **主源** |
| 日线（只有 OHLCV） | 腾讯 `fqkline/get` | 800 根 = 3.28 年 | ✅ 兜底 |
| **筹码分布** | **自算**，见 1.1 | 3.28 年 | ✅ |
| **股东人数** | 东财 `gdhs_detail_em` | 2013 年起 | ✅ |
| 定增 | 东财 `qbzf_em` | 全市场，含锁定期 | ✅ |
| 解禁 | 东财 `datacenter-web` | 按日期区间 | ✅ |
| 减持（**带公告日**） | 巨潮 `hold_change_cninfo` | 全市场 5640 行 | ✅ |
| 历史资金流 | 东财 `push2his/fflow/daykline?lmt=0` | **120 天** | ⚠️ 1.4 |
| ST / 停牌 | 腾讯快照 | 当日 | ✅ |

### 1.0 为什么主源是新浪不是腾讯（2026-09-12 改）

第一版设计把腾讯当主源，实施时发现新浪那条更好，两个原因：

**一、字段。** 新浪一个接口给全：`OHLCV + amount + turnover +
outstanding_share`。**这意味着换手率是现成的逐日精确值**，原设计里
「拉 gbjg_em 的股本变更记录 + 按变更日期阶梯前向填充」那一整套（1.2 节）
根本不必要，而且新浪这份比阶梯填充更准。

**二、覆盖。** 腾讯**没有北交所历史日线** —— 前缀 `bj` 是对的
（接口返回 data dict 不报错），但 K 线数组是空的，920268 只给当天 1 根。
338 只北交所在腾讯这条路上拿不到。

**三、配额。** 腾讯日 K 有累积配额，本机短时间打 500+ 请求后限流数十分钟，
回填反复撞墙。新浪没观察到这个问题。

代价有两个，都已处理：

- 慢：4.8s/只 对 0.33s/只。全量回填约 65 分钟（腾讯理论 30 分钟，
  但算上限流熔断实际更久）
- **不能多线程**：新浪接口内部用 `py_mini_racer` 跑 JS 解密，
  它不是线程安全的，并发调用会让 V8 **进程级 FATAL 崩溃**
  （不是抛异常，try/except 接不住）。改用**多进程**，每进程独立 V8

腾讯那条保留为兜底（`--stage daily`），符合 CLAUDE.md「数据源一律
优先+重试+兜底，不许写成唯一路径」。注意两者 `volume` 单位不同：
腾讯是**手**，新浪是**股**，差 100 倍，代码里靠「列在不在」判断而不是值的大小。

### 1.1 筹码分布：自己算，不是代理

原先判断"拿不到"是错的。**筹码分布不是交易所公布的数据，是各家行情软件
用日线自己算出来的**，算法公开。有日线 OHLCV 加精确换手率就能同源复现：

```
每个交易日：
  1. 当日成交量按 [low, high] 的三角分布撒到价格网格（峰在 (h+l+c)/3）
  2. 历史筹码按当日换手率衰减：chip = chip × (1 - turnover × decay)
  3. 新筹码 = 衰减后的历史 + 当日分配
```

原型已实现并通过**六项内部一致性检验**（160 档价格网格，800 天）：

| 检验 | 结果 | 期望 |
|---|---|---|
| 平均成本 vs 60 日 VWAP 相关系数 | 0.968 | ≈ 1 |
| 筹码质量守恒 | 1.000000 | 恒为 1 |
| 创 120 日新高时的获利盘 | 99.1% | ≈ 100% |
| 创 120 日新低时的获利盘 | 1.3% | ≈ 0% |
| 集中度 `conc_90` 分位（10/50/90） | 0.167 / 0.263 / 0.452 | 典型区间 |
| 获利盘与价格的秩相关 | 0.710 | 正且高 |

**性能**：单只 800 天 35ms，全市场 5548 只单线程 3.2 分钟。

这条路打开的不只是"集中度"一个数，而是一整组高信息量特征
（获利盘、相对平均成本位置、集中度的变化方向），见第 4 节。
真实数据复核放在阶段 0，和日线回填一起做。

### 1.2 历史换手率：精确值，不用替代品

`stock_zh_a_gbjg_em` 返回每一次股本变更的**变更日期 + 总股本 + 已上市流通A股
+ 变动原因**（浦发 69 条记录，含债转股上市等）。按变更日期做阶梯式前向填充，
就得到每个交易日的有效流通股本：

```
换手率(t) = 成交量(t) × 100 / 流通股本(t)
```

原设计里的 `vol_ratio = 当日量/N日均量` 从"替代品"降级为**补充特征**
（两者含义不同：换手率是绝对水平，vol_ratio 是相对自身的异动程度，都要）。

`stock_share_change_cninfo`（巨潮）另外带**公告日期**字段，用于处理
披露滞后，见 4.6。

### 1.3 股东人数

- `stock_zh_a_gdhs_detail_em(code)`：单只完整历史，2013 年起。
  含股东户数、增减、**户均持股数量**、**总市值**
- `stock_zh_a_gdhs(报告期)`：全市场快照，回填时用这个更快
- 频率：以季度为主，部分公司有月度/旬度披露。浦发 2023-05 以来 15 期
- 交叉校验：`总市值 / 当日收盘价 = 总股本`，浦发 2026-06-30 算得 293.5 亿股，
  与实际总股本吻合

**披露滞后是这份数据最大的坑**，处理方式见 4.6。

### 1.4 资金流：只有 120 天

`push2his/fflow/daykline/get?lmt=0` 返回 120 个交易日（约半年），含
主力/小单/中单/大单/超大单净额。`lmt` 再大也不给更多。

日线有 3.28 年而资金流只有 0.5 年，两者不对齐。按用户决定：
**主模型不含资金流，它作为独立确认层**，在那 120 天上单独检验有没有增量信息。
同时从上线第一天起每日落盘积累。

### 1.5 腾讯有速率限制

实测：5 并发连续拉 200+ 只之后被限流，返回非 JSON，持续数分钟。
原先"全市场 30 分钟"的估算**偏乐观**。

回填必须：限速（每只之间加 sleep）、指数退避重试、断点续传。
预计全量回填 60~90 分钟，分批跑。日常增量只拉最近 5 根，代价小得多。

## 2. 反对意见：这套东西最可能怎么骗人

按严重程度排序。每一条都给了应对，但**应对不等于解决**。

### 2.1 事件在时间上极度聚集（最严重）

200 只随机股票、765 个交易日的抽样实测：

```
144,740 个 (股,日) 对
其中未来 20 日内最高价涨超 50% 的：4,892 个  →  正样本率 3.38%
三年内至少出现过一次的股票：157/189 = 83%
```

事件的月份分布，前 8 名：

```
2024-09: 1218   ← 单月占全部事件的 25%
2025-12:  317
2024-10:  298
2024-11:  232
2026-04:  218
2024-02:  200
```

**2024 年 9 月一个月贡献了四分之一的正样本。** 那是 924 行情，
全市场无差别普涨，当时几乎任何特征都能"预测"成功。

在这种样本上直接训练，得到的是一个**牛市探测器**，不是选股器。它会在
回测里表现惊艳，在平盘市里一只都选不对 —— 而平盘市是绝大多数日子。

应对（三条都要做，缺一条结论就不可信）：

1. **按月分层的走向前验证**，报告每个月单独的命中率，而不是只看总平均。
   一个只在 2024-09 和 2025-12 有效的模型，要能被一眼看出来。
2. **市场状态中性化**：特征里加入当日全市场涨跌分布的分位数，让模型区分
   「这只票强」和「今天所有票都强」。
3. **同时记录绝对口径和超额口径**的标签。用户的定义是绝对 50%，模型按绝对
   口径训练（尊重定义），但评估时**必须**同时报超额口径的命中率。
   如果两者差距巨大，说明模型学到的是大盘不是个股。

### 2.2 基础比率 3.38%，别被"高命中率"骗了

随机瞎猜的命中率就是 3.38%。所以：

- 「命中率 20%」听起来一般，其实是 **6 倍**基础比率，是很好的结果。
- 「命中率 60%」几乎一定是前视偏差或过拟合，不是模型强。

**验收标准（提前定死，在 holdout 上验收）**：

| 指标 | 及格线 | 说明 |
|---|---|---|
| 清单 A 前 10 只的命中率（holdout） | ≥ 15% | 4.4 倍基础比率 |
| 剔除 2024-09 / 2025-12 后 | ≥ 10% | 证明不是只会认牛市 |
| 超额口径命中率 / 绝对口径命中率 | ≥ 0.5 | 证明学的是个股不是大盘 |
| 命中率为 0 的月份 | ≤ 1 个 | 不能整月颗粒无收 |
| 最强板块 / 最弱板块 的命中率之比 | ≤ 3 | 防止只会选北交所 |

不达标时的**分级响应**（按顺序走，不许跳步，也不许反复回头微调）：

```
1. 加特征        ← 先怀疑信息不够，而不是模型不够强
2. 换模型        ← 擂台里换一层（L0→L1→L2）
3. 改事件定义    ← 例如窗口 20 日改 30 日、阈值 50% 改 40%
4. 判定不可行    ← 三步走完仍不达标，把报告交给用户决定
```

**不允许做的事**：在验证集上反复微调超参数直到达标。那不是改进，是把验证集
变成第二个训练集。每一级响应只测一次，结果记入 `docs/breakout_log.md`，
包括失败的尝试 —— 失败记录是防止将来重复踩坑的唯一手段。

### 2.3 前视偏差

这是量化里最容易犯、后果最严重的错。具体到本线有四个入口：

1. 特征用了 t 日之后的数据（例如用整段数据算均值再标准化）。
   → 所有滚动统计必须用 `shift(1)` 后的窗口，标准化参数只能来自训练集。
2. 用「已知它涨了 50%」去挑样本，再从中找特征。
   → 标签只能来自 t+1..t+20，特征只能来自 ..t。代码层面用两个独立函数，
   各自只接收允许的切片，不共享 DataFrame。
3. 复权价的未来信息。前复权序列在每次除权时会重算**全部历史价格**，
   今天拉的 qfq 序列和三年前当时看到的不是一回事。
   → 涨跌幅用复权序列算（正确），但绝对价位阈值不要用。
4. 代码表的**幸存者偏差**：`cache/codes.csv` 是当前在市的 5548 只，
   三年内退市的票不在里面。这会**高估**正样本率（退市股通常是跌的）。
   → 影响方向已知且对"找起涨特征"偏小，但要在报告里写明，不要假装没有。

### 2.4 清单 B 的样本量会很小

清单 B 的条件是「**曾在 A 上得过 90 分以上**」且「出现见顶特征」。
如果 A 每天只有几只上 90 分，B 的池子会长期是空的，模型也没样本可训。

应对：见顶模型**独立训练**，样本取自所有真实发生过的波段（涨超 50% 后
从最高点回撤 20%），而不是只取"曾上过清单 A"的票。清单 A 的 90 分只作为
**输出时的过滤条件**，不作为训练时的样本条件。这样样本量够，逻辑也对。

### 2.5 「一个月涨 50%」在不同板块不是一回事

主板日涨停 10%，创业板/科创板 20%，北交所 30%。同样是一个月涨 50%，
主板需要连续多日强势，北交所两个涨停就够了。

应对：特征里带板块 one-hot，并且**分板块报告命中率**。如果模型选出来的
全是北交所，那不是模型好，是标签定义对北交所宽松。

## 3. 事件定义

### 3.1 起涨事件（清单 A 的标签）

```
在 t 日，若 max(high[t+1 .. t+20]) / close[t] - 1 > 0.50，则 y_up[t] = 1
```

- 窗口 20 个交易日 ≈ 一个自然月
- 用 t 日**收盘价**作基准（收盘后跑，t 日收盘价是已知的）
- 用未来最高价而不是收盘价：用户说的是"上涨超过 50%"，触及即算

同时记录**超额口径** `y_up_ex`：同一算法，但收益减去同期中证全指涨幅。
仅用于评估，不用于训练（尊重用户的绝对口径定义）。

用户要求的是"上涨前 5 个交易日的特征"。注意上式定义的是**每一个** t，
而真实起涨点只有一个。所以另外定义：

```
起涨点 t0 = 一段满足条件的连续区间里的第一天
前 5 日窗口 = [t0-4 .. t0]
```

特征在 `[t0-4 .. t0]` 这 5 天上聚合（见 4.2）。训练时正样本取 t0，
负样本从非 t0 的日子里**按月分层抽样**，保持每月正负比一致
（否则 2024-09 会淹没一切，见 2.1）。

### 3.2 见顶事件（清单 B 的标签）

```
对每一段起涨波段：
  peak  = 起涨后的最高价那一天
  end   = peak 之后首次出现 close < peak_high × 0.80 的那一天
  见顶前两日窗口 = [peak-1 .. peak]      ← 用户说的"结束前两个交易日"
  y_top[d] = 1  for d in 该窗口
```

注意这里的口径选择：用户说"波段结束（从最高点下跌超过 20%）前两个交易日"。
「结束」这个词有两种读法：

- **读法 A**：回撤 20% 那一天之前的两天 → 那时股价已经从高点跌下来了，
  发出信号为时已晚。
- **读法 B**：最高点那一天及前一天 → 在顶部附近发出信号，这才有用。

**本设计取读法 B**，因为读法 A 的信号没有交易价值。这是对用户原话的
一处主动解释，需要确认（见第 9 节问题 3）。

## 4. 特征工程

一股脑把 120 个原始指标丢进 GBDT 也能跑出结果，但那个结果在 3.38% 基础比率
加时间聚集的数据上不可信：共线的均线族会稀释重要性、量纲随行情漂移、
2024-09 的普涨会被学成"特征强"。这一节是把原始指标变成**可用特征**的完整管线。

### 4.0 三层变换（顺序不能换）

这是整套设计里最关键的工程决策。

```
原始指标  →  ① 横截面百分位  →  ② 中性化  →  ③ 组内正交  →  模型
```

**① 横截面百分位化**：每个特征换成它在**当日全市场**的分位排名。

```
feat_pct[i,t] = rank(feat[i,t] 在 t 日所有股票中) / N(t)
```

这一步直接解决第 2.1 节那个最严重的问题。2024-09 普涨时所有票的绝对涨幅、
绝对量比都高，但横截面百分位**永远是 [0,1] 上的均匀分布**。模型学到的
只能是「这只票在当天全市场中的相对位置」，不可能学成「今天大盘涨得好」。

顺带免费解决三件事：量纲统一、异常值天然截断、特征分布不随时间漂移
（2023 年的 0.9 分位和 2026 年的 0.9 分位是同一件事）。

**② 中性化**：对板块和市值回归取残差。

```
feat_neu = feat_pct - E[feat_pct | board, log_float_mktcap]
```

对应第 2.5 节的板块问题：北交所日涨停 30%，它的量价特征天然比主板极端。
不中性化的话，模型会把"是北交所"学成一个强特征，而那只是标签定义的副作用。
市值同理（小盘股波动天然大）。

**③ 组内正交**：见 4.1，同组高相关特征合并。

### 4.1 五组特征，每组回答一个问题

分组不是为了整齐，是为了**共线性可控**和**结果可解释**。组内高度相关
（这是应该的，它们在回答同一个问题），组间应当低相关。

组内处理规则：**皮尔逊相关 > 0.85 的一对，只保留单变量 IC 更高的那个**；
若一组内剩余仍 > 6 个，取该组 PCA 的前 3 个主成分。

---

**Q1 · 它在什么位置？**（position，5 个）

| 特征 | 定义 | 假设 |
|---|---|---|
| `dist_52w_high` | `close / 250日最高 - 1` | 突破前通常在前高下方不远 |
| `dist_52w_low` | `close / 250日最低 - 1` | 排除刚见底的弱势股 |
| `ma_align` | `(ma5>ma10)+(ma10>ma20)+(ma20>ma60)`，0~3 | 多头排列 |
| `ma20_slope_5` | ma20 的 5 日斜率 / 价格 | 中期趋势方向 |
| `above_ma60_days` | 连续站上 ma60 天数（截断 60） | 趋势持续性 |

均线乖离 `close/maN-1` 四个一起放会严重共线（相关普遍 > 0.9），
所以只保留 `ma_align`（离散化的排列结构）和 `ma20_slope_5`（方向），
丢掉四个乖离值本身。**这就是"不一股脑丢"的具体含义。**

---

**Q2 · 它在积蓄什么？**（compression，4 个）

启动前的典型形态是波动和量能同时收敛，然后一起放开。

| 特征 | 定义 | 假设 |
|---|---|---|
| `range_compress` | 近5日振幅均值 / 近20日振幅均值 | < 1 = 横盘收敛 |
| `vol_compress` | 近5日均量 / 近20日均量 | < 1 = 缩量 |
| `atr_ratio` | ATR14 / ATR60 | 波动率收敛 |
| `boll_width` | 20日布林带宽 / ma20 | 经典的挤压指标 |

---

**Q3 · 谁在进出？**（structure，8 个）← 本组信息量最高

筹码组（自算，见 1.1）加股东人数，这是第一版里最有希望的一组。

| 特征 | 定义 | 假设 |
|---|---|---|
| `chip_conc_90` | 90% 成本区间宽度 / 平均成本 | 越小越集中 |
| `chip_conc_chg_20` | `conc_90` 的 20 日变化 | **负 = 正在集中**，这是过程量 |
| `chip_win_ratio` | 获利盘比例 | 太高说明涨过了，太低说明套牢重 |
| `chip_avg_dev` | `close / 平均成本 - 1` | 相对全市场持仓成本的位置 |
| `chip_peak_dist` | 主力筹码峰价 / close - 1 | 上方套牢峰的距离 |
| `turn_pct` | 换手率（精确值，见 1.2） | 绝对活跃度 |
| `vol_ratio_5` | 当日量 / 5日均量 | 相对自身的异动 |
| `turn_std_20` | 20 日换手率变异系数 | 换手是否稳定 |

`chip_conc_chg_20` 是本组的核心：**静态的集中度不如集中的过程有信息量**。
一只票一直很集中说明没人交易；正在从分散走向集中，才是有人在收。

---

**Q4 · 股东人数**（holders，4 个）← 用户指定

户数减少 = 筹码向少数人集中，是经典的建仓信号。但这份数据低频、
披露滞后、且有季节性，处理不当会引入前视偏差（见 4.6）。

| 特征 | 定义 |
|---|---|
| `gdhs_chg_1` | 最近一期户数变化率（负 = 减少 = 集中） |
| `gdhs_chg_3` | 最近三期累计变化率 |
| `gdhs_down_streak` | 连续减少的期数（截断 6） |
| `gdhs_stale_days` | 距最近一期**公告日**的天数 |

`gdhs_stale_days` 必须有：它告诉模型这份数据有多旧。一个 5 天前刚披露的
户数骤降，和一个 80 天前的旧数据，含义完全不同。不给这个特征，
模型会把两者同等对待。

---

**Q5 · 相对强度与环境**（regime，5 个）

| 特征 | 定义 |
|---|---|
| `rs_20` | 近 20 日涨幅的全市场分位 |
| `rs_60` | 近 60 日涨幅的全市场分位 |
| `rs_accel` | `rs_20 - rs_60`，相对强度是否在加速 |
| `mkt_breadth` | 当日全市场上涨家数占比 |
| `mkt_ret_5` | 中证全指近 5 日涨幅 |

前三个已经是横截面量，第 ① 层对它们是幂等的。后两个是**全市场共同变量**
（当天所有股票同值），不做百分位化 —— 它们的作用恰恰是给模型一个
"今天是什么天气"的坐标，好让它把个股特征的含义按环境调整。

### 4.2 交互项：只留有假设的那几个

交互项是特征工程里最容易失控的地方（5 组两两组合能造出几百个）。
只保留**三个有明确假设**的：

| 交互项 | 假设 |
|---|---|
| `gdhs_chg_1 × chip_conc_chg_20` | 户数减少**且**筹码正在集中 = 两个独立证据同向 |
| `range_compress × vol_ratio_5` | 长期横盘收敛**且**今天突然放量 = 突破当天的形态 |
| `chip_win_ratio × dist_52w_high` | 获利盘低**且**接近前高 = 上方套牢盘薄 |

第一个是本设计对"股东人数"这个特征的真正用法：单看户数变化噪音很大
（可能只是股价下跌导致散户离场），但它和筹码集中度同向时，
才构成"有人在收集"的证据。

### 4.3 时间维度：5 天窗口怎么用

用户要的是"起涨前 5 个交易日"的特征。两种用法并行，喂给不同的模型：

- **聚合口径**（给 L0/L1）：每个特征在 `[t0-4..t0]` 上取
  **末值、均值、斜率** 三个统计量。26 个基础特征 × 3 = 78 维，加 3 个交互项
- **序列口径**（给 L2）：直接给 `[5 × 26]` 矩阵，不做聚合

保留序列口径的理由见 5.3：聚合会抹掉次序，而次序恰恰是形态的定义。

### 4.4 特征选择流程（在训练集上做，验证集不参与）

不是把 81 维全丢进去，四道筛：

```
1. 单变量 IC       |Spearman(feat, y)| < 0.01 的丢掉
2. IC 时间稳定性   按月算 IC，符号翻转率 > 40% 的丢掉
                   ← 这道最重要：不稳定的特征实盘一定失效
3. 相关剪枝        |r| > 0.85 的一对，留 IC 高的
4. L1 正则         逻辑回归 L1 再压一轮，系数为 0 的丢掉
```

第 2 道是关键。一个特征在牛市 IC 为正、熊市为负，全样本平均下来可能还不错，
但它实盘上等于抛硬币。符号翻转率这个指标直接把这类特征筛掉。

每一道筛完记录**剩余维度和被丢掉的特征名**，写进
`docs/breakout_log.md`。特征被丢掉的原因，和特征本身一样重要。

### 4.5 前视偏差的四道防线

```
1. 标签函数和特征函数物理隔离，各自只接收允许的时间切片，不共享 DataFrame
2. 所有滚动统计 shift(1)；横截面百分位只用当日已收盘的数据
3. 中性化和标准化的参数只能来自训练集，验证/holdout 用训练集拟合的参数变换
4. 低频数据按公告日对齐（见 4.6）
```

自测里构造一个**"只有未来信息才能预测"的假数据集**，模型在上面必须学不会
（AUC ≈ 0.5）。如果学会了，说明管线某处漏了未来信息。这条断言比任何
code review 都可靠。

### 4.6 低频数据的公告日对齐

股东人数、股本变更都是低频且**披露滞后**的：2026-06-30 的股东户数要到
7 月中才公告。如果按报告期对齐，模型在 7 月 1 日就用上了 6 月 30 日的数据 ——
那是标准的前视偏差，而且非常隐蔽，因为数据本身没错，错的是时间。

```
可用日 = 公告日（有就用，巨潮 stock_share_change_cninfo 带这个字段）
       = 报告期 + 15 个自然日（拿不到公告日时的保守兜底）
特征值 = 以可用日为准的前向填充
```

宁可晚用几天，不可早用一天。

## 5. 模型与验证

方针：**一切以效果为最优先。** 但在 3.38% 基础比率 + 时间极度聚集的数据上，
「效果」和「看起来有效果」的距离比模型复杂度的差距大得多。所以这一节的
结构是：模型敞开上，验证卡死。

### 5.1 数据量够不够（决定能上到哪一层）

```
样本    5548 只 × 800 天 ≈ 444 万个 (股,日) 对
正样本  3.38% ≈ 15 万个
特征    聚合口径约 120 维；序列口径 5 天 × 24 维
```

- GBDT：444 万 × 120 是**舒适区**，不是勉强
- 序列模型：15 万正样本足够训 2 层 GRU（约 10 万参数）
- 大型 Transformer：**不够**，别上。金融时序信噪比低，参数量一大就是背样本

### 5.2 模型擂台

所有模型在**同一个走向前协议**（5.4）下比，按验证集成绩选，不按先验偏好选。
项目已有这个做法（`learn/model_select.py` 的模型擂台）。

| 层 | 模型 | 输入 | 依赖 | 角色 |
|---|---|---|---|---|
| L0 | 逻辑回归 + L1 | 120 维聚合特征 | scikit-learn | **尺子**，不是备胎 |
| L1 | LightGBM | 同上 | lightgbm (~2MB) | 表格数据首选 |
| L2 | GRU / TCN | 5×24 原始序列 | torch CPU (~200MB) | 学形态而非统计量 |
| L3 | L1 + L2 概率加权 | | | 仅当两者误差互补 |

**L0 的作用是尺子**：如果 LightGBM 只比逻辑回归高 1 个百分点，说明特征已经
榨干了，继续加模型复杂度只会加过拟合风险，那时该回去挖特征而不是换模型。
没有这把尺子，就无法判断"提升"来自模型还是来自过拟合。

### 5.3 为什么序列模型在这里可能真的更强

用户要的是「起涨前 **5 个交易日**的特征」。手工聚合（最后值/均值/最大/斜率）
会丢掉**次序**信息：

```
A: 缩量横盘 4 天 → 第 5 天放量突破      ← 典型启动形态
B: 第 1 天放量 → 之后 4 天缩量回落      ← 冲高回落，含义相反
```

两者的「5 日均量」「最大量」「量的斜率」可以非常接近，聚合之后几乎不可分。
序列模型直接吃 `[5 × 24]` 矩阵，能学到这种次序结构。这是 L2 存在的理由，
也是它**可能真的赢**的地方 —— 不是因为神经网络时髦。

### 5.4 增量学习

用户明确要求。神经网络天然支持，但有**灾难性遗忘**：只拿新数据继续训练，
模型会忘掉 2024-09 那类行情。而那类行情恰恰几年才来一次，忘了就白学。

```
每日   新样本进 buffer（data/breakout/feat_<date>.parquet）
每月   replay 混合训练：按月分层从历史抽样 + 当月新样本，warm-start
每季   全量重训一次，与增量版在 holdout 上对比，
       增量版落后超过 2 个百分点就用全量版替换
```

- **L2（神经网络）走真增量**：warm-start + replay buffer
- **L1（LightGBM）不走增量**：warm start 加树会让早期树的分裂点失效，
  模型漂得厉害。GBDT 每月**全量重训**，代价是几分钟，值得

### 5.5 分数刻度（0~100）

用户要求 0~100 分。直接输出校准概率会很难看（3.38% 基础比率下模型输出
大多在 2%~25%），90 分变成不可能达到的分数。

**方案**：分数 = 校准概率在训练集分布中的**百分位** × 100。
同时在面板和邮件里，每个分数段旁边印上该分段的**历史实际命中率**：

```
95~100 分   历史命中率 23.1%   （基础比率 3.38%，6.8 倍）
90~95  分   历史命中率 17.4%
80~90  分   历史命中率 11.2%
```

**这一行必须出现在每封邮件里。** 否则「90 分」会被读成「90% 会涨」，
那是在骗人。概率校准用 isotonic regression，在验证集上拟合。

### 5.6 验证协议（这一节是整个设计的地基）

```
训练集   2023-05 .. 2025-02   （21 个月）
验证集   2025-03 .. 2025-12   （10 个月，用于选模型、调超参）
holdout  2026-01 .. 2026-09   （9 个月，锁死）
```

**holdout 的规矩**：整个开发过程中**只看一次**，在模型完全定稿之后。
看完就不许再改任何东西 —— 改了它就不再是 holdout，而是第二个验证集。

理由：擂台有 4 层模型、每层若干超参，反复在验证集上比较本身就是一种
搜索，搜到最后验证集会被间接拟合（验证集泄漏）。holdout 是唯一能给出
诚实估计的东西。

其余协议：

- **走向前**：每月重拟合，只用该月之前的数据预测该月
- **分月报告**：每个月单独的命中率，2024-09 那种月份要能被一眼认出
- **分板块报告**：防止模型只会选北交所（见 2.5）
- **剔除极端月后重报**：去掉 2024-09 和 2025-12 再算一次
- **自助置信区间**：按天自助（`learn/optimize.py` 有实现可借鉴），
  给命中率的区间而不是点估计

### 5.7 风险剔除（用户明确要求）

| 剔除项 | 数据源 | 规则 |
|---|---|---|
| ST / *ST | 腾讯快照名称 | 名称含 ST |
| 近期减持 | 巨潮 `stock_hold_change_cninfo` | 公告日在近 30 个自然日内且为减持 |
| 近期解禁 | 东财 `datacenter-web` | 未来 30 自然日内解禁且市值占比 > 5% |
| 停牌 | 腾讯快照 | 当日无成交 |
| 次新股 | 日线长度 | 上市不足 60 个交易日 |

定增：公开接口里没有稳定的定增预案数据，第一版用解禁代替
（定增的实际抛压体现在解禁上）。见第 9 节问题 2。

### 5.8 依赖分线管理

CLAUDE.md 的规矩：学习线要 scikit-learn/scipy，另两条线不许沾。爆发线同理：

```
requirements-breakout.txt    lightgbm, scikit-learn, scipy
requirements-breakout-nn.txt torch (CPU)    ← 只在 L2 进擂台时才装
```

竞价线和形态线的 `requirements.txt` 不动。L2 不装也能跑，擂台自动跳过。

## 6. 每日生产

17:00 跑，收盘后数据已定死，和形态线一样"防早不防晚"（`hard_deadline` 给到 22:00）。

```
stage=scan    拉全市场日线增量 → 算特征 → 打分 → 出清单 A
              → 查见顶模型 → 出清单 B → 落 parquet
stage=send    LLM 写文案（只写 reason/risk，不参与排序）→ 面板 → 邮件
```

**清单 A 池的持久化**：清单 B 需要知道"曾经得过 90 分以上"的票。
维护 `state/breakout/a_pool.json`：

```json
{"600000": {"first": "2026-09-12", "last": "2026-09-15", "best": 94.2}}
```

有效期 **60 个交易日**，过期自动移出。这个窗口需要确认（见第 9 节问题 4）。

清单为空是正常的，必须在邮件和面板里写明，否则用户会以为流水线坏了
（形态线已有同样的教训，CLAUDE.md 里记着）。

## 7. 在线学习闭环

用户要求"不断将当天及以后出现的符合要求的个股……不断验证加以修正"。

```
每日 17:00   落当日全市场特征快照 → data/breakout/feat_<date>.parquet
每日 17:00   落当日资金流 → data/breakout/fflow_<date>.parquet（为将来接入攒样本）
每月 1 日    回看 20 个交易日前的那一天，标注实际结果，追加训练表
每月 1 日    重新拟合 → 走向前验证 → 过闸门才替换线上参数
```

闸门沿用学习线的思路（`learn/gate.py`）：新参数必须在**验证集**上不劣于旧的，
且置信区间下界仍高于基础比率，否则拒绝。参数存
`state/breakout/model.json`，`config.yaml` 永远是人工基线。

**学习系统不许改的东西**（和竞价线同构，CLAUDE.md 硬约束 8）：
剔除规则（ST/减持/解禁）是用户定的，系统只能提案。

## 8. 分阶段计划

每个阶段都有**可检验的产出**和**止损条件**。

### 阶段 0：数据层（约 1 天）

- `src/breakout/backfill.py`：全市场 800 根日线，5 并发，落
  `data/breakout/daily.parquet`（约 5548 × 800 × 6 ≈ 2700 万格，parquet 约 200MB）
- 断点续传：中途失败能接着跑，不重头来
- 产出：一张覆盖 2023-05 .. 2026-09 的日线宽表
- **止损**：若实际耗时 > 90 分钟或成功率 < 90%，改用分批缓存策略

### 阶段 1：标注 + 特征工程（约 2 天）

- `src/breakout/label.py`：起涨、见顶两个标注函数，**物理隔离**，
  各自只接收允许的时间切片，不共享 DataFrame
- `src/breakout/chips.py`：筹码分布自算（1.1 的算法 + 六项一致性检验入自测）
- `src/breakout/features.py`：4.0 的三层变换管线 + 五组特征 + 三个交互项
- `src/breakout/select.py`：4.4 的四道筛，每道记录剩余维度和被丢的特征名
- 产出：训练表 + **数据体检报告**（正样本率、月度分布、板块分布、
  缺失率、幸存者偏差估计、每道筛的存活情况）
- **止损**：若去掉 2024-09 后正样本不足 2000 个，回到第 3 节重新定义事件

### 阶段 2：模型擂台 + 验证（约 3 天）⚠️ 关键关卡

- `src/breakout/model.py`：统一接口 `fit/predict_proba/save/load`，
  四层模型各自实现，擂台按同一协议比
  - L0 逻辑回归 + L1 正则（**先做，它是尺子**）
  - L1 LightGBM
  - L2 GRU/TCN（torch 装了才进擂台，没装自动跳过）
  - L3 概率加权集成（仅当 L1/L2 误差互补）
- `src/breakout/calib.py`：isotonic 概率校准 + 百分位分数映射
- `src/breakout/validate.py`：走向前、分月、分板块、自助置信区间
- 产出：擂台报告 + **holdout 只看一次**的最终成绩，直接回答 2.2 那张表
- **关卡**：按 2.2 的分级响应走。三级走完仍不达标，交给用户决定，
  不要自己决定"再试试"

### 阶段 2.5：增量学习（约 1 天，依赖阶段 2 选出 L2）

- 只有当擂台选中 L2（神经网络）时才做，否则 GBDT 走每月全量重训即可
- replay buffer + warm-start，季度全量重训对照
- 产出：增量版与全量版在 holdout 上的差距曲线

### 阶段 3：每日生产（约 1.5 天）

- `src/breakout/scan.py`：`--stage scan/send`
- `src/breakout/export.py`：面板 + 邮件，复用 `ths_export.PANEL_CSS` 和 `mailer`
- `prompts/breakout_analyst.md`：LLM 文案指令
- 风险剔除接线（ST/减持/解禁/停牌/次新）
- 产出：能跑出当日清单 A/B 的完整流程

### 阶段 4：整合（约 1 天）

- `src/selftest_breakout.py`：离线自测，重点钉**前视偏差**
  （构造一个"只有未来信息才能预测"的假数据集，模型必须学不会它）
- `local_run.py` 加 `--flow breakout`
- GUI 加按钮、面板 tab、状态卡片
- `build_site.py` 加 `out_breakout/`
- 计划任务 `DailyReport-Local-Breakout`，北京 17:00
- CLAUDE.md 补一节

### 阶段 5：在线学习（约 1 天）

- 每月重拟合 + 闸门
- 资金流样本积累
- 学习面板加爆发线的裁决时间线

## 附：这套东西最终能有多大用

先把预期摆正，免得实施完了才发现和想象的不一样。

基础比率 3.38%。如果 holdout 命中率做到 15%，意味着：

```
清单 A 每天给 10 只
其中约 1.5 只会在未来 20 个交易日内涨超 50%
另外 8.5 只不会
```

这已经是**4.4 倍**于随机，是一个很好的量化结果。但它不是「选出来的票会涨」，
而是「这批票里出黑马的密度比市场高 4 倍」。清单必须按这个口径去用。

清单 B 同理：它是「见顶概率显著升高」的提示，不是「明天就跌」。

如果最终 holdout 命中率落在 5%~8%（1.5~2.4 倍基础比率），我的建议会是
**不要上线**：这个强度的信号在交易成本和情绪干扰面前会被吃掉，
而每天看一份似是而非的清单，比没有清单更糟。
