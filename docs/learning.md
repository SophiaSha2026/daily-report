# 自评估 · 学习 · 迭代系统设计

竞价线的第三条支线。前两条（竞价、形态）产出清单，这一条**评估清单并调参**。

写于 2026-09-02。所有实测数字都标了日期，数据源可达性会漂，见 CLAUDE.md。

---

## 1. 目标与边界

**目标**：用「当天开盘买入、当天收盘卖出」的真实收益，检验当天打分排名的
预测力，并把检验结果转成筛选参数的迭代。

**三条不可越过的边界**（前两条继承自 CLAUDE.md 的硬约束）：

1. **`score.py` 里永远不出现模型调用。** 学习系统的产出是一份**参数文件**，
   不是一个推理服务。给定参数，排名 100% 可复现、可回测、可归因。
2. **学习系统崩了不能影响发信。** 它跑在收盘后的独立 workflow 里，
   写参数用「临时文件 + 原子重命名」，失败就保留上一版参数，早盘照跑。
3. **准入区间（涨幅 2~5%、量比 2.5~10）不自动改。** 那是用户定的规则，
   不是待优化的超参。系统只能**提案**，改不改由人决定。

## 2. 数据：有什么，没有什么

### 2.1 在线数据（每天新增）

`data/YYYY-MM/auction_<date>.parquet`，每天约 1160 行 × 34 列，
就是当天候选池的全部特征和分数。已积累 8 天（08-24 起）。

标签需要当天**收盘价**。收盘后一次 `fetch_quotes` 拿全池，
1160 只约 3.6 秒（腾讯批量，5 路并发，见 CLAUDE.md 硬约束 4）。

### 2.2 历史回填（一次性）

`daily_hist` 单次调用返回 405 根日线（2025-01 至今，20 个月），
一只票一次调用覆盖整段。5500 只 × 4 路并发 ≈ 7 分钟。

### 2.3 历史竞价数据：全渠道实测（2026-09-02）

这一节是整套设计的分水岭，所以每条都实测过，不是查资料得来的。

| 渠道 | 结果 |
|---|---|
| 腾讯**当日**分笔 `stock_zh_a_tick_tx_js` | ✅ 竞价是单独一笔：`09:25:02 9.35 3997手 3736812元`。但**没有日期参数**，只有当天 |
| 腾讯分笔按日期下载 `action=download&d=YYYYMMDD` | ❌ 试了 09-02/09-01/08-28/08-21/07-01 五个日期两只票，全部返回「暂无数据」，接口已废 |
| 腾讯 m1 分钟 `ifzq.gtimg.cn/kline/mkline` | ❌ 硬顶 320 根 ≈ 1.3 个交易日，`cnt` 调到 3000 也一样 |
| 新浪 1min `CN_MarketDataService` | ❌ 每天首根是 **09:31**，竞价量混在里面；`datalen=1023` 只覆盖 5 天 |
| 新浪 5min | ❌ 首根 09:35，同样混；1023 根覆盖 21 天 |
| 新浪当日分笔页 | ❌ 只有当天 |
| 东财全部分钟接口 | ❌ 整站不通（CLAUDE.md 硬约束 5） |

首根污染有多严重，用实测数据说：浦发银行 2026-09-01 竞价成交 3997 手，
而 09:31 那根 1 分钟线是 25971 手。**竞价只占首根的 15%**，
拿首根当竞价量能的代理，85% 是噪声。

**免费渠道的结论：历史竞价量能和竞价轨迹，取不到。**

### 2.3b 唯一的付费出路：Tushare `stk_auction_o`

`stk_auction_o`（股票开盘集合竞价数据）返回竞价段的
`open / high / low / close / vol / amount / vwap`，历史从 2025 年 1 月起。

它几乎补齐了缺失的那 45%：

| 我们的特征 | 映射 | 保真度 |
|---|---|---|
| `auc_amount` / `auc_ratio` | `amount` | 精确 |
| `t3_chg` | `close` | 精确 |
| `slope` | `close − open` | 近似：起点是 09:15，我们的 T1 是 09:19:40 |
| `dive` | `high − close` | 近似，但方向和量级对 |
| 假涨停撤单 | `high ≥ 涨停×0.9` 且 `close < 涨停×0.5` | **比线上那版还准**，high 抓的是整段峰值而不是一个采样点 |
| `monotonic` | `close == high` | 弱代理，聊胜于无 |

代价：**需要单独申请权限**，不是普通积分能开的。

所以 `learn/sources.py` 写成**可插拔适配器**：

- `free`（默认）：只回填 H 块四个维度
- `tushare`：填了 `TUSHARE_TOKEN` 就自动切到全特征

换源不改任何下游代码，`dataset.py` 之后的东西看到的都是同一张表，
只是列的完整度不同，用一个 `feature_completeness` 标记区分。

### 2.3c 于是六个打分维度分成两块（免费源下）：

| 块 | 维度 | 权重和 | 历史可还原 |
|---|---|---|---|
| **H 块** | gap / position / sector / continuity | 0.55 | ✅ |
| **L 块** | volume / trend | 0.45 | ❌ 只能靠在线积累 |

这是整套设计的地基。任何声称能用历史数据训练全部六个维度的做法，
都是在用代理变量冒充竞价量能，学出来的关系搬到线上是错的。

### 2.4 回填的三个已知偏差

写在这里，不为它们单独做工程，但报告里要标注：

1. **幸存者偏差**。`cache/codes.csv` 是今天的代码表，一年前退市的票不在里面。
   对「开盘买、收盘卖」这种单日持仓影响轻微，但会略微高估收益。
2. **板块表漂移**。`sector_map.parquet` 是当前成分，用它标注一年前的板块，
   等于用了未来信息。`sector` 维度的历史结论要打折看。
3. **除权除息**。日线取的是不复权价，同日的开盘/收盘一致，
   所以**标签不受影响**；但 `gap_pct` 依赖昨收，除权日会算错。
   用数据源自带的 `涨跌幅` 列反解出复权后的昨收来修。

## 3. 标签设计

```
r_di = close_di / open_di − 1
```

`open` 就是竞价撮合价，也就是我们的买入价。所以 `r` 是**可执行收益**，
不是纸面收益。

排除三类不可执行的样本：

- 当天停牌（无开盘价）
- 竞价即一字板（`one_word`，买不进，打分里本来就直接剔除）
- 开盘价与我们快照里的 `auc_price` 偏离超过 0.5%（数据不一致，标为脏样本）

### 3.1 三步日内中性化

这一步是**收敛的第一道保险**，比损失函数本身更重要。

```
第一步  y  = r − median_d(r)          # 全池中位数，不是均值
第二步  y  = clip(y, q1_d, q99_d)     # 按当日 1%/99% 分位缩尾
第三步  ỹ = y / MAD_d(y)              # MAD = 1.4826 × median(|y − median y|)
```

- **减中位数**：大盘跌 2% 的那天，几乎所有票的 close/open 都是负的。
  不减掉，损失就被「今天大盘怎么走」主导，而我们的特征根本不预测大盘。
- **缩尾**：一只票收盘一字跌停，`y` 会是 −10σ，一个样本能翻转整天的梯度。
- **除 MAD**：波动大的日子天然贡献更大的数值。除掉之后，
  安静的一天和暴动的一天在损失里**权重相同**。

用均值和标准差不行：涨跌停会让 std 爆炸，一只 +20% 的票能把均值拽偏。

## 4. 损失函数

### 4.1 为什么不能直接优化「前 10 的实际收益」

前 10 是硬截断，是参数的阶跃函数：绝大多数地方梯度为 0，
在名次交换点上是不连续的跳变。8 维参数 + 60 天数据，
直接优化它等于在噪声面上做随机游走。

**所以：优化平滑代理，汇报硬指标。** 两者的最优方向一致，
但代理有梯度，硬指标有意义。

### 4.2 单日目标：软 Top-K 超额收益

对第 d 天通过硬性排除的集合 `A_d`：

```
π_i = exp(s_i / τ_d) / Σ_j exp(s_j / τ_d)        i ∈ A_d
G_d = Σ_i π_i · ỹ_i
```

`π` 是按分数加权的组合权重。温度 `τ_d` **每天单独二分求解**，使得

```
exp(H(π)) = K = 10          H 是 π 的熵
```

即「有效持仓只数 = 10」。这样 `G_d` 的含义是：
*一个把资金按分数集中到大约 10 只票上的组合，当天的标准化超额收益*。

三个极限行为对得上直觉：

- `τ → 0`：全押分数最高那只，`G_d → ỹ` 的第一名
- `τ → ∞`：等权全池，`G_d → 0`（因为 `ỹ` 已经日内中性化，均值为 0）
- 打分和收益无关：`G_d` 的期望为 0

**每天重新解 τ 而不是固定** —— 候选池大小、分数分布每天都在变，
固定温度会让池子大的日子实际持仓分散、池子小的日子过度集中。

### 4.3 跨天聚合：Huber M 估计，不是算术平均

这是**收敛的第二道保险**，直接回答"不受某一天随机浮动影响"。

```
Ĝ(θ) = argmin_m  Σ_d  w_d · ρ_c( (G_d(θ) − m) / σ̂ )
```

- `ρ_c` 是 Huber 损失，`c = 1.345`（对高斯有 95% 效率的标准取值）
- `σ̂ = MAD({G_d})`
- `w_d` 是 LLM 归因给出的日权重，见第 8 节

Huber 的性质：任何**单日**对 `Ĝ` 的影响力上限是 `c·σ̂`。
某天我们的头号选票封涨停（`ỹ ≈ +8`），它对参数更新的推力
和一个 +1.3σ 的普通好日子**完全一样**。算术平均没有这个性质。

### 4.4 完整损失

```
L(θ) = − Ĝ(θ)
       + λ_a(N) · Σ_k ((θ_k − θ⁰_k) / σ_k)²      锚定项
       + λ_1    · Σ_k |θ_k − θ^prev_k| / σ_k     稀疏项
       + Σ_k barrier(θ_k ∈ box_k)                 箱约束
```

`σ_k` 取参数 k 箱约束的半宽，把所有参数放到同一量纲上。

**锚定项 —— 收敛的第三道保险。** `θ⁰` 是 `config.yaml` 里人工写的那一版。
系数按证据量衰减：

```
λ_a(N) = λ₀ · n₀ / (n₀ + N)          n₀ = 120 天
```

`n₀ = 120` 的含义是：**人工配置值 120 个交易日的证据**。

| N（已积累天数） | λ_a / λ₀ | 实际效果 |
|---|---|---|
| 8 | 0.94 | 基本冻结，动不了 |
| 60 | 0.67 | 只有很强的证据能推动 |
| 120 | 0.50 | 数据和先验各占一半 |
| 250 | 0.32 | 数据主导 |
| 500 | 0.19 | 先验只剩防跑偏作用 |

这是标准的贝叶斯收缩。它的好处是**不需要人为设一个"多少天以后开始学"的
开关**，权重是连续过渡的，而且早期天然保守。

**稀疏项 —— 顺带解决可读性。** L1 惩罚「相对上一版的改动」，
最优解会让大多数参数**原地不动**，只有少数几个跳到新值。
于是每次变更邮件里都是「这一个旋钮从 A 变成 B」，
而不是「八个数全变了 0.3%」。可读性是设计目标，不是副产品。

### 4.5 汇报用的硬指标（不参与优化）

| 指标 | 含义 |
|---|---|
| `IC_d` | 当天分数与 `ỹ` 的 Spearman 秩相关 |
| `IC` 均值 / `ICIR` | `mean(IC)`，`mean(IC)/std(IC)` |
| `top10_ret` | 真前 10 等权，`mean(r)`（原始收益，不中性化） |
| `top10_excess` | 真前 10 等权，`mean(y)`（减了当日中位数） |
| `hit_rate` | 前 10 里 `y > 0` 的比例 |
| `decile_spread` | 分数第一档减第十档的 `y` |

`top10_excess` 是最终评判标准。`G_d` 只是它的可优化替身。

## 5. 收敛保护：五道闸

前面三道在损失函数里（中性化、Huber、锚定）。剩下两道在**接受门**上。

一个候选参数 `θ*` 要真正落地，必须**全部**通过：

| # | 闸门 | 默认值 | 理由 |
|---|---|---|---|
| 1 | 最少天数 | `N ≥ 60` | 少于这个数，任何改善都在噪声里 |
| 2 | 走向前验证 | 滚动窗口拟合，尾部 `20%` 天数留出测试 | 样本内改善不算数 |
| 3 | 自助显著性 | 按**天**重抽样 2000 次，`P(Ĝ*ᵒᵒˢ > Ĝᵖʳᵉᵛᵒᵒˢ) ≥ 0.90` | 按天不按行：同一天内收益高度相关，按行重抽会把置信区间算窄好几倍 |
| 4 | 步长上限 | 单参数每次移动 ≤ 箱宽的 10%，一次最多动 2 个参数 | 即使统计上过关，也不允许一步跨太大 |
| 5 | 行为回放 | 用 `θ*` 重放最近 20 天，任何一天的前 10 变动 ≤ 40% | 挡住"数学上更优但行为上发疯"的解 |
| 6 | 冷却期 | 距上次接受 ≥ 10 个交易日 | 防止连续微调把系统推着走 |

任何一条不过 → **不改**，把不过的原因写进 `state/learning_status.json`。

### 5.1 这套闸门意味着什么：诚实的时间表

A 股日内信号的日 IC 标准差经验上在 0.10~0.20。取 0.15：

```
N 天后，IC 均值的标准误 = 0.15/√N
90% 置信下能检出的 IC 改善：
     8 天  ->  0.073      （现在）
    60 天  ->  0.025
   120 天  ->  0.018
   250 天  ->  0.012
```

**所以第一次真正的参数变更，合理预期在 3~5 个月后。**
比这更快的系统，改的是噪声不是信号。

这不是缺陷，是这个数据量下的物理上限。所以第 12 节专门讲
**冷启动期这套系统交付什么** —— 答案是分析，不是调参。

## 6. 两层学习

### 6.1 H 层（历史回填层，一次性 + 季度重跑）

**数据**：一年以上的日线重建候选池和 H 块特征，约 250 天 × 1200 只。

**能学什么**：`gap_pct_peak`，`position` / `sector` / `continuity` 的内部形状参数，
以及 **H 块内部四个维度的相对权重**。

**不能学什么**：`volume` 和 `trend` 的任何参数（数据里根本没有），
以及 H 块整体与 L 块的混合比例。

**怎么用**：H 层的产物是**更好的 `θ⁰`**，不是最终参数。
它把先验从"我拍的数"升级成"250 天数据支持的数"，
然后在线层仍然按第 5 节的闸门在这个先验附近迭代。

### 6.2 L 层（在线层，每天）

**数据**：`data/YYYY-MM/auction_*.parquet` + 当日标签，每天 +1。

**学什么**：全部 8 个可学参数，但受 H 层给的先验和第 5 节的闸门约束。

### 6.3 参数分级

| 级别 | 参数 | 行为 |
|---|---|---|
| **可学** | 6 个权重（和为 1，5 个自由）、`gap_pct_peak`、`auc_ratio_score_hi`、`auc_ratio_decay` | 过闸门就自动改，改了发邮件 |
| **只提案** | `gap_pct_min/max`、`auc_ratio_min/max`、`min_score`、`top_n` | 系统给出建议值和证据，**必须人工点头**才写入 |
| **冻结** | 三次快照时刻、发信双阈值、`min_auc_amount_wan`、硬性排除的判定顺序 | 学习系统碰不到 |

准入区间放在「只提案」而不是「可学」，是因为它们是用户明确定的规则。
2026-09-02 用户刚把它们退回初版，系统无权撤销这个决定。

## 7. GBDT 的角色：老师，不是排序器

有了回填数据（30 万行 × 15 特征），梯度提升树在统计上站得住了。
但**它不当排序器**，理由：

1. 会废掉硬约束 1 的精神：黑箱排名无法归因，用户也无法用规则语言讨论它
2. 只能拿到 55% 的特征（L 块历史缺失），线上跑会系统性偏
3. 用户关心规则本身 —— 刚花了一整轮把规则退回初版

它当**两件事**：

### 7.1 天花板估计

在同一套走向前切分上，比较：

```
我们的六维打分器  OOS IC = a
GBDT（同特征集）  OOS IC = b
```

- `b − a` 小 → 函数形式没损失多少，继续调阈值收益不大，**该停手**
- `b − a` 大 → 我们的形式在丢信息，把这个结论交给 LLM Agent 去查是哪一块丢的

这是一个**知道什么时候该停止调参**的信号，本身就有价值。

### 7.2 形状老师

对 `gap_pct` 做偏依赖图（PDF/SHAP）：GBDT 认为的最优高开幅度在哪？
如果它给出的峰值在 2.9% 而我们写的是 3.5%，那就是一条有数据支持的
`gap_pct_peak` 提案，走第 5 节的闸门。

**这样既拿到了树模型的非参数拟合能力，又保住了生产打分器的透明性。**

### 7.3 深度学习：不用，理由写清楚

- 特征是 15 个表格型变量，样本按天分块。这个设定下 GBDT 稳定优于神经网络，
  是公开可复现的结论，不是偏好
- 有效样本量受**天数**限制（同日截面残差高度相关），不是 30 万行
- 神经网络的参数量会超过我们能验证的自由度，闸门 3 永远过不了

留一个扩展点：`learning.method` 支持 `coord` / `nelder` / `gbdt_teacher`，
以后天数上去了要加别的，接口在那儿。

## 8. LLM Agent 的三个通道

Agent 用 Opus，走 claude-code-action，和竞价线同一套调用方式
（`claude_args`，`--json-schema`，见 CLAUDE.md 硬约束 7）。

**它的输出永远不直接变成参数。** 三个通道，都可审计：

### 通道 1 · 归因（每天）

**输入**：当天误差最大的两组各 8 只票

- 高分低收益：分数前 20 里 `ỹ` 最差的
- 低分高收益：分数后 50% 里 `ỹ` 最好的

**任务**：WebSearch 查这些票当天发生了什么，把每一只归到一个**固定枚举**里：

| 标签 | 含义 |
|---|---|
| `个股利空` | 竞价后出现的公司层面坏消息 |
| `个股利好` | 同上，好消息 |
| `板块轮动` | 整个板块当天掉头 |
| `大盘系统性` | 指数级别的行情主导，个股特征无从预测 |
| `流动性陷阱` | 盘口太薄，实际买不到那个价 |
| `情绪退潮` | 高标集体失败，涨停梯队崩了 |
| `形态失效` | 查不到原因，形态本身没生效 |
| `数据异常` | 我们的数据错了 |

同时给整天一个 `day_regime` 标签和一句话说明。
输出落 `state/llm_eval/<date>.json`。

**枚举是固定的**，因为要计数、要做时间序列。自由文本无法聚合。

### 通道 2 · 日权重

`day_regime` 映射成优化器里的 `w_d`：

```
数据异常     -> 0.0     我们自己的数据错了，这天不该参与学习
大盘系统性   -> 0.35    特征不预测指数，全权重只贡献方差
情绪退潮     -> 0.70    真实但罕见的状态，降权不剔除
其余         -> 1.0
```

映射表写在 config 里。**给定 JSON，优化器完全确定**——
LLM 的影响是可复现的，因为它的输出被落盘了。

### 通道 3 · 提案

Agent 可以提两类东西：

- **参数提案**：直接给一组 `θ*`。它和优化器给的候选**走同一道闸门**，
  统计说了算。Agent 提得再有道理，过不了闸门就不改。
- **新特征提案**：自然语言描述（比如「加一个『板块内竞价涨幅离散度』」）。
  进 `state/feature_backlog.jsonl`，每月汇总发邮件，**必须人工实现**，
  永不自动上线。

### 通道 4（不存在）

Agent **不能**：改代码、改准入区间、改冻结参数、绕过闸门、写 `state/learned.yaml`。

## 9. 工程结构

```
src/
  cfg.py                    合并加载器：config.yaml（人工 θ⁰）+ state/learned.yaml（当前 θ）
  eval_daily.py             入口。--stage label / analyze / learn / apply / report
  learn/
    labels.py               收盘后抓收盘价 -> data/labels/YYYY-MM/label_<date>.parquet
    backfill.py             一次性：拉一年日线 -> 重建候选池和 H 块特征 + 标签
    dataset.py              多天装载 + 日内中性化 + 缩尾 + MAD
    vscore.py               向量化打分器（score.py 的孪生体，被等价性测试钉住）
    objective.py            τ 求解、G_d、Huber 聚合、正则、箱约束
    optimize.py             坐标下降 / Nelder-Mead + 走向前 + 按天自助
    teacher.py              GBDT 天花板估计 + gap 形状偏依赖
    gate.py                 六道闸
    apply.py                原子写 state/learned.yaml + 版本历史
    report.py               变更邮件 + 面板区块
prompts/
  eval_analyst.md           归因指令
state/
  learned.yaml              当前生效的 θ（早盘流水线读这个）
  theta_history.jsonl       每次接受的 θ、证据、时间
  learning_status.json      最新一次评估的全部指标和闸门结论
  llm_eval/<date>.json      Agent 归因
  feature_backlog.jsonl     新特征提案
data/
  labels/YYYY-MM/           每日标签
  train/backfill_*.parquet  回填训练表
.github/workflows/
  learn.yml                 6-自评估与迭代  16:30 BJT
```

### 9.1 参数怎么进生产

`config.yaml` **保持人工书写，永远是 θ⁰**。学到的参数写 `state/learned.yaml`，
`cfg.load()` 做浅合并。好处：

- `git diff config.yaml` 永远显示的是人的意图，不被机器改动淹没
- 删掉 `state/learned.yaml` 就是一键回到人工基线
- 两个文件的差就是「机器学到了什么」，可以直接渲染进邮件

### 9.2 失败隔离

- 独立 workflow，跑在 16:30，和早上 07:30 那条毫无交集
- `apply` 写临时文件再 `os.replace`，中途崩溃不会留下半个 YAML
- `cfg.load()` 读 `learned.yaml` 失败 -> 记一条 warning，用纯 `config.yaml` 继续
- LLM 那步吞掉所有异常、退出码永远 0（沿用 `collect_llm.py` 的做法）

### 9.3 向量化打分器的等价性

`vscore.py` 为了让优化器能在几十毫秒里评估一次目标函数而存在
（30 万行逐行调 `score_one` 要 3 秒，Nelder-Mead 500 次迭代就是 25 分钟）。

它是 `score.py` 的**孪生体**，必须逐位一致。
`selftest_learn.py` 用 2000 个随机样本断言
`max|vectorized − score_one| < 1e-9`。这条断言一红，整个学习系统作废。

## 10. 变更邮件

只在**接受了变更**的当天发。内容：

1. **参数差表**：哪几个旋钮动了，从什么到什么，动了百分之多少
2. **证据**：`Ĝ` 的样本外改善、自助 90% 置信区间、参与的天数、六道闸各自的结论
3. **行为影响**：用新旧参数重放最近 20 天，列出会新进榜 / 掉出榜的票
4. **LLM 叙述**：这段时间归因标签的分布，Agent 认为改动对应的是什么现象
5. **回滚方法**：一行命令

没接受变更的日子**不发邮件**，只在竞价面板底部加一行学习状态，
和 `state/learning_status.json` 里留全量记录。

## 11. 冷启动期（前 60 个交易日）交付什么

参数一动不动，但这套系统从**第一天**就产出：

- **每日 IC 和前 10 实际超额收益**，以及累计净值曲线
  （「每天开盘买前 10、收盘卖」到底赚不赚钱）
- **分维度 IC**：gap / volume / trend / position / sector / continuity
  六个维度，哪个真的预测收益，哪个是摆设
- **GBDT 天花板**：我们的函数形式离数据上限还有多远
- **归因计数**：失败的票里，多少是个股利空、多少是大盘、多少是形态本身失效
- **回填层的历史结论**：一年数据下 H 块四个维度各自的表现

**这些才是前几个月的产品。** 参数自动迭代是它的长期形态，不是近期价值。

## 12. 已知的设计取舍

1. **只学「开盘到收盘」这一个持有期。** 不学隔夜、不学多日。
   理由：这是当前清单唯一明确对应的交易动作，标签和动作必须一一对应。
2. **不做交易成本建模。** 印花税千分之一（卖出）+ 佣金，约 0.13% 单边。
   `top10_excess` 汇报时会减掉一个固定的 `cost_bp`，但不进优化目标
   （它是常数，不改变排序）。
3. **不处理涨跌停无法成交。** 开盘一字板已经被 `one_word` 剔除；
   收盘封死跌停卖不掉的情况会高估亏损，方向是保守的，不修。
4. **板块表用当前成分回填历史**，是轻度未来信息。`sector` 维度的
   历史结论标注为「有偏，仅供参考」，在线层不受影响。

## 13. 点火后的架构结论（2026-09-03）

四次点火 + 全量擂台（401 个交易日回填，走向前 + 按天自助）测出三段事实：

1. **旋钮已到头。** 对 θ⁰ 做单参数扰动探针，箱内梯度 ≤0.03/σ，
   九个可学参数还能挖的改善不足 0.1%。头两次点火优化器原地不动
   不是没信号，是正则强度（λ₀=8 拍脑袋值）比实测信号大十倍；
   按测量校准（λ₀=0.25，L1=0.02）后能动了，但可动幅度本来就小。
2. **天花板在函数形式里。** 同一套特征、同一套走向前切分：
   基线 OOS IC 0.022 / 前10日均超额 +0.69%；RankHuber 0.117 / +1.40%；
   ExtraTrees 0.123 / +2.14%。缺口 2~3 倍，不是参数能追平的。
3. **擂台胜者恰好透明。** 奥卡姆规则选中 RankHuber（线性，ICIR 1.65 落在
   ExtraTrees 1.73 的 90% 区间内）。「不许黑箱排序」拦的是不可解释，
   不拦系数可打印的线性回归。

于是架构定型为四层：

```
第 0 层 · 准入（政策层）  人定，机器只提案       gap 2~5% / 量比 2.5~10 / 流动性
第 1 层 · 排序（模型层）  确定性、可复现、可归因   今天：手写六维加权
                                              演进：秩特征线性模型（影子转正）
第 2 层 · 治理（闸门层）  一切参数变更的必经之路   七道闸 + 校准锚定 + 稀疏化投影
第 3 层 · 影子（证据层）  新形式先并行记账        learn/shadow.py，逐日双榜对比
```

**影子转正的路径**：`stage_learn` 每天 refit 影子模型并在在线真值快照上
记录双方 IC / 前10超额 / 榜单重合度（`state/learning_status.json::shadow`，
学习面板可见）。当在线积累 ≥ 30 天且影子按天自助 P(更好) ≥ 0.90 时，
系统生成**切换提案**摆给用户——切换动作本身永远是人工的，
和准入区间同级。

顺带修的两个治理缺陷（第三次点火暴露）：

- Nelder-Mead 不产生精确稀疏解，连续解会触及全部参数被闸门 4 拦下。
  `optimize.sparsify` 把连续解投影成「最多 max_moves 个意图」：
  取 |Δ|/σ 最大的方向、步长截顶、权重组等比再归一。
- 闸门 4 改按**意图**计数：动一个权重必然带出其余权重的和为 1 再归一，
  那是结果不是决定，不占改动名额；步长上限仍对所有实际变化生效。


## 14. 特征与数据扩容 v2（2026-09-03，用户批准实施）

### 14.1 新特征（7 个，全部进影子/擂台，不进 score.py）

| 特征 | 含义 | 来历 |
|---|---|---|
| `sector_gap_med` | 同板块池内竞价涨幅中位数 | LLM 归因提案转正：09-02 前 8 名里 7 只压在两个当日集体掉头的板块上，原特征只看昨日板块热度 |
| `sector_up_frac` | 同板块池内高开比例 | 同上 |
| `mkt_gap_med` | 全池竞价涨幅中位数 | regime v1 的确定性载体 |
| `mkt_up_frac` | 全池高开比例 | 同上 |
| `gap_x_mkt` | gap × 市场中位（交互） | 全截面常数在按天秩归一下会归零，交互项才能让模型学到条件行为 |
| `aucr_x_breadth` | 量能 × 市场宽度（交互） | 同上 |
| `cauc_ratio_prev` | 昨日尾盘竞价额/昨日全天额 | 新数据源，见 14.3 |

全部在 `model_select.prep_features` 一处计算，在线快照和回填表同一条代码路径，
杜绝口径分叉。竞价窗口内可得，无未来信息。

### 14.2 regime 拆分的取舍

选了「一个模型 + 市场状态特征 + 交互项」，没选「按状态切多个模型」：
后者每个子模型的有效样本立刻掉到一两百天，闸门 3 过不了。
LLM 的 day_regime 继续做样本权重（通道 2），两条路互补：
特征管「模型内的条件行为」，权重管「哪些天值得学」。

### 14.3 数据源再盘点（2026-09-03 实测）

| 源 | 结论 |
|---|---|
| Tushare `stk_auction_c` 尾盘集合竞价(14:57-15:00) | ✅ 可用，5500+ 只/天，2025-01 起。机构收盘定价行为，已回填并入特征 |

### 14.4 通道 4：Opus 审稿人（learn/llm_review.py）

参数变更过完七道闸后、落地前，Opus 拿完整证据包（改动、闸门数字、
近期归因分布、影子对比）做交叉检查——找「数字对但叙事不对」的矛盾。
输出枚举 stance（支持/保留意见/反对）+ 理由，落盘可审计。

两种模式（config `learning.llm.review_mode`）：
`advisory`（默认）意见附在变更邮件里；`veto` 下「反对」把变更搁置成
`state/held_change.json`，人工 `--stage apply-held` 才落地。
LLM 只能按暂停不能按删除，人永远有终审权。失败 fail-open。
