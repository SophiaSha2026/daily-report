# 自评估 · 学习 · 迭代系统设计

竞价线的第三条支线。前两条（竞价、形态）产出清单，这一条**评估清单并调参**。

写于 2026-09-02。所有实测数字都标了日期，数据源可达性会漂，见 CLAUDE.md。

---

## 1. 目标与边界

**目标**：用「当天开盘买入、当天收盘卖出」的真实收益，检验当天打分排名的
预测力，并把检验结果转成筛选参数的迭代。

**三条不可越过的边界**（前两条继承自 CLAUDE.md 的硬约束）：

1. **`score.py` 里永远不出现模型调用。** 学习系统的产出是一份**参数文件**，
   不是一个推理服务。给定参数，排名 100% 可复现、可回测、可归因。
2. **学习系统崩了不能影响发信。** 它跑在收盘后的独立 workflow 里，
   写参数用「临时文件 + 原子重命名」，失败就保留上一版参数，早盘照跑。
3. **准入区间（涨幅 2~5%、量比 2.5~10）不自动改。** 那是用户定的规则，
   不是待优化的超参。系统只能**提案**，改不改由人决定。

## 2. 数据：有什么，没有什么

### 2.1 在线数据（每天新增）

`data/YYYY-MM/auction_<date>.parquet`，每天约 1160 行 × 34 列，
就是当天候选池的全部特征和分数。08-24 起积累，2026-09-16 是 17 个在线真值日
（`eval_daily` 的日志和 `learning_status.json` 里的 `train_source` 会写当天的数）。

标签需要当天**收盘价**。收盘后一次 `fetch_quotes` 拿全池，
1160 只约 3.6 秒（腾讯批量，5 路并发，见 CLAUDE.md 硬约束 4）。

### 2.2 历史回填（一次性）

`daily_hist` 单次调用返回 405 根日线（2025-01 至今，20 个月），
一只票一次调用覆盖整段。5500 只 × 4 路并发 ≈ 7 分钟。

### 2.3 历史竞价数据：全渠道实测（2026-09-02）

这一节是整套设计的分水岭，所以每条都实测过，不是查资料得来的。

| 渠道 | 结果 |
|---|---|
| 腾讯**当日**分笔 `stock_zh_a_tick_tx_js` | ✅ 竞价是单独一笔：`09:25:02 9.35 3997手 3736812元`。但**没有日期参数**，只有当天 |
| 腾讯分笔按日期下载 `action=download&d=YYYYMMDD` | ❌ 试了 09-02/09-01/08-28/08-21/07-01 五个日期两只票，全部返回「暂无数据」，接口已废 |
| 腾讯 m1 分钟 `ifzq.gtimg.cn/kline/mkline` | ❌ 硬顶 320 根 ≈ 1.3 个交易日，`cnt` 调到 3000 也一样 |
| 新浪 1min `CN_MarketDataService` | ❌ 每天首根是 **09:31**，竞价量混在里面；`datalen=1023` 只覆盖 5 天 |
| 新浪 5min | ❌ 首根 09:35，同样混；1023 根覆盖 21 天 |
| 新浪当日分笔页 | ❌ 只有当天 |
| 东财全部分钟接口 | ❌ 整站不通（CLAUDE.md 硬约束 5） |

首根污染有多严重，用实测数据说：浦发银行 2026-09-01 竞价成交 3997 手，
而 09:31 那根 1 分钟线是 25971 手。**竞价只占首根的 15%**，
拿首根当竞价量能的代理，85% 是噪声。

**免费渠道的结论：历史竞价量能和竞价轨迹，取不到。**

### 2.3b 唯一的付费出路：Tushare `stk_auction_o`

`stk_auction_o`（股票开盘集合竞价数据）返回竞价段的
`open / high / low / close / vol / amount / vwap`，历史从 2025 年 1 月起。

**「它几乎补齐了缺失的那 45%」这句话 2026-09-16 被实测推翻，整段作废。**
`stk_auction_o` 那根 bar 不是 09:15~09:25 的竞价段，而是「09:25 撮合价 ->
09:30 之后」的一根早盘 K 线：集合竞价只有一个成交价，纯竞价 bar 必然
`high == low == open == close`，而实测 `high == low` 只占 45.5%；和日线对表，
`open` == 日线开盘 99.4%，`close` 只有 56%（219 万行）。第三方交叉验证同向：
线上 09:25:10 的真采样 == 日线开盘 99.7%、== `ts.open` 99.6%、
== `ts.close` 只有 42.7%（`learn/backfill.py::merge_auction` 的注释里有这组数）。

所以现在**只 merge 两列**，撮合之后的字段一列都不进表：

| 我们的特征 | 映射 | 保真度 |
|---|---|---|
| `auc_price` / `gap_pct` | `open` | 撮合价。与日线开盘不一致率 0.23%（旧口径拿 `close` 是 41.6%），`backfill.check_auction_price` 是哨兵，超 1% 就抛 |
| `auc_amount` / `auc_ratio` | `amount` | **偏大**：含开盘后成交，比线上 09:25:10 真值中位高 25%~33%，`auc_ratio` 跟着偏大约 23%，量能准入两边判定不一致 16.6% |
| `t1_chg` / `t2_chg` / `t3_chg` | 一律 = `gap_pct` | 竞价轨迹历史上取不到 |
| `slope` / `dive` | 恒 `0.0` | 同上 |
| `monotonic` | 恒 `False` | 同上 |
| 假涨停撤单 | 不可观测 | 回填 4/407621 触发、线上 281/21036（准入后 0% vs 5.1%） |

`close / high / low / vwap` **一列都不 merge 进来**（`merge_auction` 只
rename `open -> auc_price`、`amount -> auc_amount`）：留着就会有人再拿它们
当 T1/T2/T3，而那样算出来的 `slope` 是**开盘后的涨跌**，与标签
`r = close/open − 1` 相关 +0.15，和线上真 slope 相关只有 −0.03 —— 那是前视泄漏，
不是弱代理。给中性值和线上 `traj_ok=False` 时 `run_auction.build_features`
的口径完全一致（`f_trend` 恒 0.5，假涨停和跳水两条规则都不触发）。
`selftest_train.check_auction_caliber` 把这一整套钉住。

代价：**需要单独申请权限**，不是普通积分能开的。

所以 `learn/sources.py` 写成**可插拔适配器**：

- `free`（默认）：只回填 H 块四个维度
- `tushare`：填了 `TUSHARE_TOKEN` 就运行时探测（`probe_ts`）。`stk_auction_o`
  只当 H 用；要让 volume 变成可学，得换 `stk_auction`（非 `_o`）拿纯竞价额，
  换之前必须先用重叠日实测 `median(ts_amount / 线上 auc_amount)` 落在
  [0.98, 1.02]

换源不改任何下游代码，`dataset.py` 之后的东西看到的都是同一张表，
只是列的完整度不同。**注意训练表上没有 `feature_completeness` 这一列**
（早期设计里有，没落地）：完整度是 `sources.completeness()` 算出来的，
`--stage backfill` 会把它和可学维度打进日志，真正约束下游的是
`restrict_box` 裁过的箱（见 2.3d）。

### 2.3c 于是六个打分维度分成两块（免费源和 `stk_auction_o` 下都一样）：

| 块 | 维度 | 权重和 | 历史可还原 |
|---|---|---|---|
| **H 块** | gap / position / sector / continuity | 0.55 | ✅ |
| **L 块** | volume / trend | 0.45 | ❌ 只能靠在线积累 |

这是整套设计的地基。任何声称能用历史数据训练全部六个维度的做法，
都是在用代理变量冒充竞价量能，学出来的关系搬到线上是错的。

2026-09-16 前 `_o` 被 `sources.completeness()` 当成 `FULL`（六维全可学），
那是按接口名想当然。现在它返回 `H`：轨迹是开盘后的涨跌，竞价额含开盘后成交
（2.3b）。`trend` 在**任何**历史源上都不可学（它要 09:19:40 / 09:23:30 两个
撤单前的虚拟撮合价，属 L1 快照流，Tushare 的竞价包和分钟线都不含）。

### 2.3d 可学维度会被代码裁掉，不是靠人记住

`learn/sources.py` 三个函数是这条规则的唯一实现：

```
completeness()    'H'（免费源 / stk_auction_o）或 'H+V'（stk_auction）
learnable_dims()  'H' -> DIMS_H 四维；'H+V' -> 再加 volume
dims_from_cfg(c)  config.learning.backfill.learnable_dims 是唯一真相，
                  没写才退回上面的探测（probe_ts 要联网，离线场合走配置）
restrict_box(box, theta0, dims)
                  把 DIM_PARAMS 里不属于可学维度的键**钉死** lo=hi=θ⁰
```

裁法是钉死不是删键：`objective.project` 要求箱里 `scoring.weights.*` 那组的
和恰好为 1，删掉 `volume` / `trend` 两个键会让剩下四个被归一到 1，
加上仍在生效的两个 0.20，总权重变成 1.4。钉死则既不动生产语义，
又让优化器在这两维上一步也迈不出去。

**只打日志不裁是没用的**：闸门比的是同一份被污染的目标函数，回填里
`slope` 恒 0、`f_trend` 恒 0.5，优化器只会把 `w_trend` 推到下界去给别的维度
腾预算 —— 那不是学到的结论，是数据缺失，而且它一路过闸就会落地。
入口在 `eval_daily._learn_box(c)`，`stage_learn` 和会诊的参数提案共用它；
`selftest_train.check_learnable_box` 钉住裁剪行为。

注意：如果 `state/learned.yaml` 里某个后来被钉死的键已经学到了别的值，
锚定项会被 1e-12 的尺度放大 —— 转为不可学之前要先 rollback 那个键。

### 2.4 回填的已知偏差

**完整清单在 `src/learn/backfill.py` 的模块 docstring 里，2026-09-16 起是
九条**（撮合价、轨迹、竞价额、候选池、ST 判定、除权、一字板…），那份跟着
代码走，这里只留最常被问到的三条：

1. **幸存者偏差**。`cache/codes.csv` 是今天的代码表，一年前退市的票不在里面。
   对「开盘买、收盘卖」这种单日持仓影响轻微，但会略微高估收益。
2. **板块表漂移**。`sector_map.parquet` 是当前成分，用它标注一年前的板块，
   等于用了未来信息。`sector` 维度的历史结论要打折看。
3. **除权除息**。日线取的是不复权价，同日的开盘/收盘一致，
   所以**标签不受影响**；但 `gap_pct` 依赖昨收，除权日会算错。
   「用数据源自带的 `涨跌幅` 列反解复权后的昨收」这句 2026-09-16 前是
   无条件做的，而三路日线里只有东财那路的 `涨跌幅` 是复权口径
   （`datasource` 用 `chg_adj` 列标出来）：`cache/hist_daily.parquet` 的
   2188865 个非首行 100% 是不复权比值，反解是恒等式，等于没修。
   现在只有 `chg_adj=True` 的行才反解；其余按「涨跌幅绝对值超过涨跌停幅度
   0.5pp」判出除权日并把那一行丢掉（以前留下 236 行 `gap_pct` 低到 −66.76%
   的不可能样本）。现金分红那种小除息判不出来，约 0.1% 的行 `gap_pct` 偏低
   （11443 个除权事件里 1805 个落在训练表内，误差中位 0.66pp、P90 5.07pp，
   按 2~5% 准入有 55 行判定翻转）。

## 3. 标签设计

```
r_di = close_di / open_di − 1
```

`open` 就是竞价撮合价，也就是我们的买入价。所以 `r` 是**可执行收益**，
不是纸面收益。

排除三类不可执行的样本：

- 当天停牌（无开盘价）
- 竞价即一字板（`one_word`，买不进，打分里本来就直接剔除）
- 开盘价与我们快照里的 `auc_price` 偏离超过 0.5%（数据不一致，标为脏样本）

### 3.1 三步日内中性化

这一步是**收敛的第一道保险**，比损失函数本身更重要。

```
第一步  y  = r − median_d(r)          # 全池中位数，不是均值
第二步  y  = clip(y, q1_d, q99_d)     # 按当日 1%/99% 分位缩尾
第三步  ỹ = y / MAD_d(y)              # MAD = 1.4826 × median(|y − median y|)
```

- **减中位数**：大盘跌 2% 的那天，几乎所有票的 close/open 都是负的。
  不减掉，损失就被「今天大盘怎么走」主导，而我们的特征根本不预测大盘。
- **缩尾**：一只票收盘一字跌停，`y` 会是 −10σ，一个样本能翻转整天的梯度。
- **除 MAD**：波动大的日子天然贡献更大的数值。除掉之后，
  安静的一天和暴动的一天在损失里**权重相同**。

用均值和标准差不行：涨跌停会让 std 爆炸，一只 +20% 的票能把均值拽偏。

## 4. 损失函数

### 4.1 为什么不能直接优化「前 10 的实际收益」

前 10 是硬截断，是参数的阶跃函数：绝大多数地方梯度为 0，
在名次交换点上是不连续的跳变。8 维参数 + 60 天数据，
直接优化它等于在噪声面上做随机游走。

**所以：优化平滑代理，汇报硬指标。** 两者的最优方向一致，
但代理有梯度，硬指标有意义。

### 4.2 单日目标：软 Top-K 超额收益

对第 d 天通过硬性排除的集合 `A_d`：

```
π_i = exp(s_i / τ_d) / Σ_j exp(s_j / τ_d)        i ∈ A_d
G_d = Σ_i π_i · ỹ_i
```

`π` 是按分数加权的组合权重。温度 `τ_d` **每天单独二分求解**，使得

```
exp(H(π)) = K = 10          H 是 π 的熵
```

即「有效持仓只数 = 10」。这样 `G_d` 的含义是：
*一个把资金按分数集中到大约 10 只票上的组合，当天的标准化超额收益*。

三个极限行为对得上直觉：

- `τ → 0`：全押分数最高那只，`G_d → ỹ` 的第一名
- `τ → ∞`：等权**硬性排除之后的那个子集**，`G_d →` 该子集的 `mean(ỹ)`
- 打分和收益无关：`G_d` 的期望**就是那个子集的 `mean(ỹ)`**，不是 0
  （零基准这件事只对「全池」成立，而我们从来不在全池上算）

第二条以前写的是「等权全池，`G_d → 0`（因为 ỹ 已中性化，均值为 0）」，
那是个不成立的定理：`ỹ` 按当日**全池**中位数中性化，而软 TopK 只在**准入后**
的子集上算，这个子集的均值系统性偏正（413 天实测 p10/p50/p90 =
−0.51 / +0.21 / +1.01，75% 的天 |均值| > 0.2）。见 `objective.day_G` 的注释
（2026-09-16 审计 F1-7）。同一处还改了空池天：准入后一只不剩返回 `NaN`
而不是 0.0 —— 那天根本没有持仓，对参数没有任何信息，写 0.0 会被当成一个
正常观测挤进 Huber 聚合和自助（`aggregate` 把非有限的天整天剔除）。

**每天重新解 τ 而不是固定** —— 候选池大小、分数分布每天都在变，
固定温度会让池子大的日子实际持仓分散、池子小的日子过度集中。

### 4.3 跨天聚合：Huber M 估计，不是算术平均

这是**收敛的第二道保险**，直接回答"不受某一天随机浮动影响"。

```
Ĝ(θ) = argmin_m  Σ_d  w_d · ρ_c( (G_d(θ) − m) / σ̂ )
```

- `ρ_c` 是 Huber 损失，`c = 1.345`（对高斯有 95% 效率的标准取值）
- `σ̂ = MAD({G_d})`，**只在 `w_d > 0` 的天上算**
- `w_d` 是 LLM 归因给出的日权重，见第 8 节

`σ̂` 那句不是细节。`objective.huber_location` 2026-09-16 起在**算起点和尺度
之前**就把 `w = 0` 的天（LLM 判「数据异常」）剔掉；以前只有 IRLS 那一步带权，
`median` 和 `MAD` 用的是含 w=0 天的全部 `x`，那些天照样决定 `σ̂`，进而决定
其它天的截断阈值 `c·σ̂`。实测注入 10 个 w=0 的极端日，闸门 2 的 ΔĜ 漂 3.7e-3
（当次闸门差距的 32%）；异常日过半时 `σ̂` 完全由它们决定，Huber 直接退化成
算术平均（审计 F1-4）。`bootstrap_better` 一直是先剔再抽，剔完两边口径才一致。

`MAD = 0`（半数以上样本取同一个值）时退回**加权中位数**，不是加权均值：
均值在那个分支上没有影响力上限，6 个 0 加一个 5.0 就被拖到 0.502，
「单日暴走不能主导」当场失效（审计 F1-3）。

Huber 的性质：任何**单日**对 `Ĝ` 的影响力上限是 `c·σ̂`。
某天我们的头号选票封涨停（`ỹ ≈ +8`），它对参数更新的推力
和一个 +1.3σ 的普通好日子**完全一样**。算术平均没有这个性质。

### 4.4 完整损失

```
L(θ) = − Ĝ(θ)
       + λ_a(N) · Σ_k ((θ_k − θ⁰_k) / σ_k)²      锚定项
       + λ_1    · Σ_k |θ_k − θ^prev_k| / σ_k     稀疏项
       + Σ_k barrier(θ_k ∈ box_k)                 箱约束
```

`σ_k` 取参数 k 箱约束的半宽，把所有参数放到同一量纲上。

**锚定项 —— 收敛的第三道保险。** `θ⁰` 是 `config.yaml` 里人工写的那一版。
系数按证据量衰减：

```
λ_a(N_train) = λ₀ · n₀ / (n₀ + N_train)          n₀ = 120 天
```

`n₀ = 120` 的含义是：**人工配置值 120 个交易日的证据**。

`N_train` 是**进入拟合的训练天数**，不是训练表里的全部天数：走向前先按
`split_days(days, oos_frac)` 做纯尾部切分，样本外那 20% 一行都没参与 `fit`，
不该算进「喂给优化器的证据量」。`eval_daily.stage_learn` 传的是 `len(tr)`
（`src/eval_daily.py:682-683`），所以
`N_train ≈ 已积累天数 × (1 − oos_frac)`，当前 `oos_frac = 0.20`。

2026-09-16 前这里传的是全部天数 `n`：401 天的表上 `λ_a` 比按 321 天算低
15.5%（N→∞ 时趋向 20%），连续解离 `θ⁰` 远了 19%（0.756σ vs 0.615σ），
第二个意图是 `position` 还是 `trend` 的排序余量从 0.053σ 缩到 0.003σ
（审计 F1-5）。方向上锚定只会更紧，和「别让它在噪声上乱走」一致，
所以 `λ₀` 不必重校。

| N_train（进入拟合的训练天数） | λ_a / λ₀ | 实际效果 |
|---|---|---|
| 8 | 0.94 | 基本冻结，动不了 |
| 60 | 0.67 | 只有很强的证据能推动 |
| 120 | 0.50 | 数据和先验各占一半 |
| 250 | 0.32 | 数据主导 |
| 321（401 天表的训练段） | 0.27 | 当前量级 |
| 500 | 0.19 | 先验只剩防跑偏作用 |

这是标准的贝叶斯收缩。它的好处是**不需要人为设一个"多少天以后开始学"的
开关**，权重是连续过渡的，而且早期天然保守。

**稀疏项 —— 顺带解决可读性。** L1 惩罚「相对上一版的改动」，
最优解会让大多数参数**原地不动**，只有少数几个跳到新值。
于是每次变更邮件里都是「这一个旋钮从 A 变成 B」，
而不是「八个数全变了 0.3%」。可读性是设计目标，不是副产品。

### 4.5 汇报用的硬指标（不参与优化）

`optimize.Problem.metrics` 实际产出这几个（键名就是下表左列）：

| 指标 | 含义 |
|---|---|
| `ic_mean` / `ic_std` / `icir` | 当天分数与 `ỹ` 的 Spearman 秩相关，在**过准入全池**上算 |
| `top_excess` | **当天真会发出去的那张榜**等权，`mean(y_raw) − 双边成本` |
| `hit_rate` | 同一张榜里 `y_raw − 成本 > 0` 的比例 |
| `avg_pool` / `avg_sent` | 过准入只数 / 真发出去的只数（两个数差约 48%，混成一个就是在报一张不存在的榜） |

三条口径细节（2026-09-16 审计，都不报错但会改结论）：

- **「前 10」有两个定义。** 生产链路是 `score.py::rank` + `run_auction.select`：
  未被硬性排除**且** `round(score,1) >= output.min_score`，再取前 `top_n`。
  学习线以前只用 `~rej` 取前 K，把从没发过信的低分票算进成绩和闸门 5 的换手：
  404 天里 97 天（23.5%）两张榜不是同一批票，在线 17 天里 4 天不同
  （09-11 池 10 只 / 实发 5 只，09-14 15/8，09-16 12/6）。现在只有一份实现：
  `optimize.production_order`。
- **IC 不套那条 45 分线**，因为区间截断会机械压低相关性（同一份表
  `ic_mean` 0.0100 vs 0.0180，提案的优劣还会反号）；成绩和换手套。
- **收益用未缩尾的 `y_raw`**：缩尾（`winsor_q=0.01`）是给目标函数防梯度翻转的，
  不该出现在给人看的数字里（在线 17 天 168 只选中票有 10 只被截，
  09-11 汇报 −5.826% 实为 −6.057%）。成本按单边 `cost_bp`(13) 一买一卖各扣一次。

`top_excess` 是最终评判标准。`G_d` 只是它的可优化替身，而且**刻意**不套
45 分线（见 `Problem._day_arrays`：那条线是 θ 的函数，加进掩码会让样本集
随 θ 漂，优化器多出一根「把分数整体抬高来加长名单」的杠杆）。

## 5. 收敛保护：接受门

前面三道保护在损失函数里（中性化、Huber、锚定）。剩下的全在**接受门**上 ——
这张表写的时候是六条，代码里现在是八条 Check（见表下的注）。

一个候选参数 `θ*` 要真正落地，必须**全部**通过：

| # | 闸门 | 默认值 | 理由 |
|---|---|---|---|
| 1 | 最少天数 | `N ≥ 60` | 少于这个数，任何改善都在噪声里 |
| 2 | 样本外改善 + 块一致性 | 一次拟合：`split_days` 按时间把尾部 `oos_frac`(0.20) 的天数留出测试，要求整段 `Ĝ_oos` 更好，**且**样本外切成 `oos_blocks`(3) 个连续块后至少 `oos_min_blocks_better`(2) 块同向改善 | 样本内改善不算数；整段一个数会把块间分歧抹平 |
| 3 | 自助显著性 | 按**天**重抽样 2000 次，`P(Ĝ*ᵒᵒˢ > Ĝᵖʳᵉᵛᵒᵒˢ) ≥ 0.90` | 按天不按行：同一天内收益高度相关，按行重抽会把置信区间算窄好几倍 |
| 4 | 步长上限 | 单参数每次移动 ≤ 箱宽的 10%，一次最多动 2 个参数 | 即使统计上过关，也不允许一步跨太大 |
| 5 | 行为回放 | 用 `θ*` 重放最近 20 天，任何一天的前 10 变动 ≤ 40% | 挡住"数学上更优但行为上发疯"的解 |
| 6 | 冷却期 | 距上次接受 ≥ 10 个交易日 | 防止连续微调把系统推着走 |

任何一条不过 → **不改**，把不过的原因写进 `state/learning_status.json`。

两条和代码对表时要注意的：

- **闸门 2 不是「滚动窗口拟合」**，它只切一次（`optimize.split_days` 是纯尾部
  切分）。块一致性是 2026-09-16 加的：整段那个尾窗每天只往后挪一天，相邻两次
  裁决的 `te` 集合 Jaccard 0.976~0.988，「连着几次都过」几乎等于「过了一次」；
  而 83 天单窗口的配对差标准误（实测 se=0.0091）和效应量（−0.0096）同量级。
  09-16 那个提案把同一个 `te` 切三块是 +0.0095 / −0.0175 / −0.0134 一正两负，
  整段的 −0.0115 把分歧全抹平了（审计 F1-6）。
- 习惯上叫「七道闸」（这张表六条 + 第七道在线稳健性），但
  `learn/gate.py::evaluate` 现在实际产出**八条 Check**：最前面多一条 0 号
  「权重和为 1」的守卫（2026-09-16 加，挡住 LLM 直接给值的提案让 Σw≠1 —— 实测
  只把 trend 0.20 -> 0.23 夹进箱送进来，Σw=1.03 一路过闸落地，`score.py` 的
  `raw = 100·Σw·v` 满分变 103，等于同时放松 `min_score=45` 和相对削弱各项扣分，
  18 天真实快照里 ≥45 分的行 280 -> 299）。第七道「在线稳健性」只否决不要求，
  见 13 节和 config `online_veto_p` / `online_min_days`。

### 5.1 这套闸门意味着什么：诚实的时间表

A 股日内信号的日 IC 标准差经验上在 0.10~0.20。取 0.15：

```
N 天后，IC 均值的标准误 = 0.15/√N
90% 置信下能检出的 IC 改善：
     8 天  ->  0.073      （现在）
    60 天  ->  0.025
   120 天  ->  0.018
   250 天  ->  0.012
```

**所以第一次真正的参数变更，合理预期在 3~5 个月后。**
比这更快的系统，改的是噪声不是信号。

这不是缺陷，是这个数据量下的物理上限。所以第 12 节专门讲
**冷启动期这套系统交付什么** —— 答案是分析，不是调参。

## 6. 两层学习

### 6.1 H 层（历史回填层，一次性 + 季度重跑）

**数据**：一年以上的日线重建候选池和 H 块特征，约 250 天 × 1200 只。

**能学什么**：`gap_pct_peak`，`position` / `sector` / `continuity` 的内部形状参数，

**学什么**：全部 8 个可学参数，但受 H 层给的先验和第 5 节的闸门约束。

**2026-09-15 现状说明（审计）**：L 层「每天 +1」没有实现。`eval_daily._load_train`
只读 `data/train/backfill_*.parquet`（2026-09-03 决定用回填点火，源截止
2026-09-02），在线真值只做第七道闸和影子对比。于是 09-04 到 09-14 七次裁决的
Ĝ_oos / P 逐位相同，每天的「拟合」是同一份数据的重复计算。

**2026-09-15 用户决定：在线真值天并进训练表**（`eval_daily._load_train`）。

## 7. GBDT 的角色：老师，不是排序器

有了回填数据（30 万行 × 15 特征），梯度提升树在统计上站得住了。
但**它不当排序器**，理由：

1. 会废掉硬约束 1 的精神：黑箱排名无法归因，用户也无法用规则语言讨论它
2. 只能拿到 55% 的特征（L 块历史缺失），线上跑会系统性偏
3. 用户关心规则本身 —— 刚花了一整轮把规则退回初版

它当**两件事**：

### 7.1 天花板估计

在同一套走向前切分上，比较：

```
我们的六维打分器  OOS IC = a
GBDT（同特征集）  OOS IC = b
```

- `b − a` 小 → 函数形式没损失多少，继续调阈值收益不大，**该停手**
- `b − a` 大 → 我们的形式在丢信息，把这个结论交给 LLM Agent 去查是哪一块丢的

这是一个**知道什么时候该停止调参**的信号，本身就有价值。

> **2026-09-16：13 节里那组天花板数字（RankHuber 0.117 / +1.40%、
> ExtraTrees 0.123 / +2.14%）需要重测。** 它们是在 2026-09-16 之前的训练表上
> 算的，那份表的 `slope` / `dive` / `monotonic` 是从 `stk_auction_o` 的
> 开盘后字段造出来的代理值，和标签相关 +0.15（2.3b），差距里有多少是
> 「函数形式」、多少是「泄漏」分不开。同一次审计还改了候选池口径、
> `sector_members` 口径、生产口径榜单和净化，训练表正在重建。



### 7.2 形状老师

对 `gap_pct` 做偏依赖图（PDF/SHAP）：GBDT 认为的最优高开幅度在哪？
如果它给出的峰值在 2.9% 而我们写的是 3.5%，那就是一条有数据支持的
`gap_pct_peak` 提案，走第 5 节的闸门。

**这样既拿到了树模型的非参数拟合能力，又保住了生产打分器的透明性。**

### 7.3 深度学习：不用，理由写清楚

- 特征是 15 个表格型变量，样本按天分块。这个设定下 GBDT 稳定优于神经网络，
  是公开可复现的结论，不是偏好
- 有效样本量受**天数**限制（同日截面残差高度相关），不是 30 万行
- 神经网络的参数量会超过我们能验证的自由度，闸门 3 永远过不了

### 7.4 优化器实际是怎么跑的（`optimize.fit`）

不是坐标下降，也不是「坐标下降或 Nelder-Mead 二选一」——`config` 里从来
没有过 `learning.method` 这个键，代码里只有一条路：

```
多起点 Nelder-Mead：起点 1 = θ_prev，另外 n_starts−1(=4) 个是
                    θ_prev + N(0, 0.15σ) 的抖动，各跑一遍取最优
                    （maxiter 600，xatol 1e-4，fatol 1e-6）
每次求值前先 O.project 投影回「箱 ∩ {Σw=1}」
拟合完 OPT.sparsify 把连续解投影成「最多 max_moves(2) 个意图」
```

选导数无关方法是因为目标函数不可导：softmax 里有二分求根，L1 在 `θ_prev`
处还有尖点。多起点是首次点火的教训：只从 `θ_prev` 出发，L1 的尖点让单纯形
一步都迈不出去（每个小移动的罚分都大于局部目标改善），看起来像「没有信号」，
其实是被自己的正则钉死在起点。所有起点都收回 `θ_prev`，那才是真的没信号。

`sparsify` 存在的理由：Nelder-Mead 的单纯形在所有维度上一起挪，不会像坐标
下降那样给出精确零，第三次点火实测 9 个参数各漂一点、被闸门 4 按「动了 9 个」
拦下。规则是按 `|Δ|/σ` 排序取前 `max_moves` 个（小于 `min_frac`(0.02)·σ 的
算噪声不算意图），每个意图的步长截到 `max_step_frac`(0.10) × 箱宽，
权重类意图改完后其余权重等比再归一保持和为 1。

## 8. LLM Agent 的三个通道

Agent 用 Opus，走 claude-code-action，和竞价线同一套调用方式
（`claude_args`，`--json-schema`，见 CLAUDE.md 硬约束 7）。

**它的输出永远不直接变成参数。** 三个通道，都可审计：

### 通道 1 · 归因（每天）

**输入**：当天误差最大的两组各 8 只票

- 高分低收益：分数前 20 里 `ỹ` 最差的
- 低分高收益：分数后 50% 里 `ỹ` 最好的

**任务**：WebSearch 查这些票当天发生了什么，把每一只归到一个**固定枚举**里：

| 标签 | 含义 |
|---|---|
| `个股利空` | 竞价后出现的公司层面坏消息 |
| `个股利好` | 同上，好消息 |
| `板块轮动` | 整个板块当天掉头 |
| `大盘系统性` | 指数级别的行情主导，个股特征无从预测 |
| `流动性陷阱` | 盘口太薄，实际买不到那个价 |
| `情绪退潮` | 高标集体失败，涨停梯队崩了 |
| `形态失效` | 查不到原因，形态本身没生效 |
| `数据异常` | 我们的数据错了 |

同时给整天一个 `day_regime` 标签和一句话说明。
输出落 `state/llm_eval/<date>.json`。

**枚举是固定的**，因为要计数、要做时间序列。自由文本无法聚合。

### 通道 2 · 日权重

`day_regime` 映射成优化器里的 `w_d`：

```
数据异常     -> 0.0     我们自己的数据错了，这天不该参与学习
大盘系统性   -> 0.35    特征不预测指数，全权重只贡献方差
情绪退潮     -> 0.70    真实但罕见的状态，降权不剔除
其余         -> 1.0
```

映射表写在 config 里。**给定 JSON，优化器完全确定**——
LLM 的影响是可复现的，因为它的输出被落盘了。

### 通道 3 · 提案

Agent 可以提两类东西：

- **参数提案**：直接给一组 `θ*`。它和优化器给的候选**走同一道闸门**，
  统计说了算。Agent 提得再有道理，过不了闸门就不改。
- **新特征提案**：自然语言描述（比如「加一个『板块内竞价涨幅离散度』」）。
  进提案台账，**必须人工实现**，永不自动上线。

2026-09-16 审计发现这条通道从上线起没人消费（`param_proposal` /
`feature_proposal` 落了盘，没有代码读它们）。现在由学习会诊统一接手：
`learn/council/run.attribution_proposals` 把归因文件里的提案并进台账
`state/council/proposals.jsonl`，参数类自动走 `eval_daily.evaluate_candidate`
（和 `stage_learn` 共用 `_judge`，同一套七道闸），过闸的等控制台批准。

### 通道 4（不存在）

Agent **不能**：改代码、改准入区间、改冻结参数、绕过闸门、写 `state/learned.yaml`。

### 通道 5 · 学习会诊（2026-09-16 起，docs/council.md）

每次学习更新末尾，六个 Opus 5（max 推理）进程并行，各看一个角度
（差距定位 / 波动还是真差距 / 特征体检 / 市场环境 / 数据与流程 / 改进提案），
主审汇总成 JSON（差距在哪、多大、为什么、是不是真的、怎么改）。两条线都看，
起涨预测的清单真值和同期全市场基准由 `breakout/truth.py` 算。
提案走通道 3 同一条路，台账在 `state/council/proposals.jsonl`；起涨常量和
去掉的特征批准后写 `state/breakout/overrides.json`（`daily.load_overrides`
只认 `SCORE_MIN` / `CAP_A` / `MIN_STREAK` / `BOARD_ADJ` / `drop_features`
五个键，删掉文件就回到代码里的默认值）。全过程（每一步读了什么、查了什么、
说了什么）落 `out_learn/council.html`，控制台「面板 -> 学习会诊」里能看。
边界同通道 4：LLM 不排序、不改参数、失败不阻断。设计和第一次真跑的成本、
踩的四个坑都在 `docs/council.md`。

## 9. 工程结构

```
src/
  cfg.py                    合并加载器：config.yaml（人工 θ⁰）+ state/learned.yaml（当前 θ）
  eval_daily.py             入口。--stage label / brief / learn / llm / race / council /
                            intraday / exits / backfill / build-train / apply-held /
                            rollback / status / all
  localenv.py               tools/local.env -> os.environ，本机每个入口先调一次
  learn/
    labels.py               收盘后抓收盘价 -> data/labels/YYYY-MM/label_<date>.parquet
    backfill.py             一次性：拉历史日线+竞价 -> 重建候选池和 H 块特征 + 标签
    sources.py              回填源适配器 + 可学维度裁剪（2.3d）
    dataset.py              多天装载 + 日内中性化 + 缩尾 + MAD
    vscore.py               向量化打分器（score.py 的孪生体，被等价性测试钉住）
    objective.py            τ 求解、G_d、Huber 聚合、正则、箱 ∩ Σw=1 投影
    optimize.py             生产口径榜单（production_order）+ 多起点 Nelder-Mead
```

### 9.1 参数怎么进生产

`config.yaml` **保持人工书写，永远是 θ⁰**。学到的参数写 `state/learned.yaml`，
`cfg.load()` 做浅合并。好处：

- `git diff config.yaml` 永远显示的是人的意图，不被机器改动淹没
- 删掉 `state/learned.yaml` 就是一键回到人工基线
- 两个文件的差就是「机器学到了什么」，可以直接渲染进邮件

### 9.2 失败隔离

- 独立流程，跑在 16:30 之后（本机计划任务 `DailyReport-Local-Learn`），
  和早盘那条毫无交集
- `apply` 写临时文件再 `os.replace`，中途崩溃不会留下半个 YAML
- `cfg.load()` 读 `learned.yaml` 失败 -> 记一条 warning，用纯 `config.yaml` 继续
- LLM 那步吞掉所有异常、退出码永远 0（沿用 `collect_llm.py` 的做法）

### 9.3 向量化打分器的等价性

`vscore.py` 为了让优化器能在几十毫秒里评估一次目标函数而存在
（30 万行逐行调 `score_one` 要 3 秒，Nelder-Mead 500 次迭代就是 25 分钟）。

它是 `score.py` 的**孪生体**，必须逐位一致。
`selftest_learn.py` 用 2000 个随机样本断言
`max|vectorized − score_one| < 1e-9`。这条断言一红，整个学习系统作废。

## 10. 变更邮件

只在**接受了变更**的当天发。内容：

1. **参数差表**：哪几个旋钮动了，从什么到什么，动了百分之多少
2. **证据**：`Ĝ` 的样本外改善、自助 90% 置信区间、参与的天数、每一道闸各自的结论
3. **行为影响**：用新旧参数重放最近 20 天，列出会新进榜 / 掉出榜的票
4. **LLM 叙述**：这段时间归因标签的分布，Agent 认为改动对应的是什么现象
5. **回滚方法**：一行命令

没接受变更的日子**不发邮件**，只在竞价面板底部加一行学习状态，
和 `state/learning_status.json` 里留全量记录。

## 11. 冷启动期（前 60 个交易日）交付什么

参数一动不动，但这套系统从**第一天**就产出：

- **每日 IC 和前 10 实际超额收益**，以及累计净值曲线
  （「每天开盘买前 10、收盘卖」到底赚不赚钱）
- **分维度 IC**：gap / volume / trend / position / sector / continuity
  六个维度，哪个真的预测收益，哪个是摆设
- **GBDT 天花板**：我们的函数形式离数据上限还有多远
- **归因计数**：失败的票里，多少是个股利空、多少是大盘、多少是形态本身失效
- **回填层的历史结论**：一年数据下 H 块四个维度各自的表现

**这些才是前几个月的产品。** 参数自动迭代是它的长期形态，不是近期价值。

## 12. 已知的设计取舍

1. **只学「开盘到收盘」这一个持有期。** 不学隔夜、不学多日。
   理由：这是当前清单唯一明确对应的交易动作，标签和动作必须一一对应。
2. **不做交易成本建模。** 印花税千分之一（卖出）+ 佣金，约 0.13% 单边。
   `top10_excess` 汇报时会减掉一个固定的 `cost_bp`，但不进优化目标
   （它是常数，不改变排序）。
3. **不处理涨跌停无法成交。** 开盘一字板已经被 `one_word` 剔除；
   收盘封死跌停卖不掉的情况会高估亏损，方向是保守的，不修。
4. **板块表用当前成分回填历史**，是轻度未来信息。`sector` 维度的
   历史结论标注为「有偏，仅供参考」，在线层不受影响。

## 13. 点火后的架构结论（2026-09-03）

四次点火 + 全量擂台（401 个交易日回填，走向前 + 按天自助）测出三段事实：

1. **旋钮已到头。** 对 θ⁰ 做单参数扰动探针，箱内梯度 ≤0.03/σ，
   九个可学参数还能挖的改善不足 0.1%。头两次点火优化器原地不动
   不是没信号，是正则强度（λ₀=8 拍脑袋值）比实测信号大十倍；
   按测量校准（λ₀=0.25，L1=0.02）后能动了，但可动幅度本来就小。
2. **天花板在函数形式里。** 同一套特征、同一套走向前切分：
   基线 OOS IC 0.022 / 前10日均超额 +0.69%；RankHuber 0.117 / +1.40%；
   ExtraTrees 0.123 / +2.14%。缺口 2~3 倍，不是参数能追平的。
   **【2026-09-16 标注：这一组数字口径已变更，需重测。】** 它们算在旧训练表上，
   那份表的竞价轨迹是 `stk_auction_o` 开盘后字段造的代理值（和标签相关 +0.15），
   候选池比生产多一条规则、少一条规则（两边日均只重合 70%），
   `sector_members` 数的是整个候选池（94.6% 的行 `f_sector` 饱和，线上 26.9%），
   成绩还是「过准入后取前 10」而不是生产实发的那张榜。表正在重建，
   重建后这三行要整体重算再下结论。
3. **擂台胜者恰好透明。** 奥卡姆规则选中 RankHuber（线性，ICIR 1.65 落在
   ExtraTrees 1.73 的 90% 区间内）。「不许黑箱排序」拦的是不可解释，
   不拦系数可打印的线性回归。

于是架构定型为四层：

```
第 0 层 · 准入（政策层）  人定，机器只提案       gap 2~5% / 量比 2.5~10 / 流动性
第 1 层 · 排序（模型层）  确定性、可复现、可归因   今天：手写六维加权
                                              演进：秩特征线性模型（影子转正）
第 2 层 · 治理（闸门层）  一切参数变更的必经之路   七道闸 + 校准锚定 + 稀疏化投影
第 3 层 · 影子（证据层）  新形式先并行记账        learn/shadow.py，逐日双榜对比
```

**影子转正的路径**：`stage_learn` 每天 refit 影子模型并在在线真值快照上
记录双方 IC / 前10超额 / 榜单重合度（`state/learning_status.json::shadow`，
学习面板可见）。当在线积累 ≥ 30 天且影子按天自助 P(更好) ≥ 0.90 时，
系统生成**切换提案**摆给用户——切换动作本身永远是人工的，
和准入区间同级。

顺带修的两个治理缺陷（第三次点火暴露）：

- Nelder-Mead 不产生精确稀疏解，连续解会触及全部参数被闸门 4 拦下。
  `optimize.sparsify` 把连续解投影成「最多 max_moves 个意图」：
  取 |Δ|/σ 最大的方向、步长截顶、权重组等比再归一。
- 闸门 4 改按**意图**计数：动一个权重必然带出其余权重的和为 1 再归一，
  那是结果不是决定，不占改动名额；步长上限仍对所有实际变化生效。

### 14.2 regime 拆分的取舍

选了「一个模型 + 市场状态特征 + 交互项」，没选「按状态切多个模型」：
后者每个子模型的有效样本立刻掉到一两百天，闸门 3 过不了。
LLM 的 day_regime 继续做样本权重（通道 2），两条路互补：
特征管「模型内的条件行为」，权重管「哪些天值得学」。

### 14.4 通道 4：Opus 审稿人（learn/llm_review.py）

### 15.1 闸门 2 与闸门 3 量的不是同一件事

闸门 2 比的是两个 Huber 位置估计之差 `Ĝ(θ*) − Ĝ(θ)`，闸门 3 自助的是**逐日配对差**
`G_d(θ*) − G_d(θ)` 的 Huber 位置。两者可以一正一负：配对差消掉了日间共同波动，
对「新参数是否稳定地略好」更敏感；位置差看的是整体水平。两条都要过是刻意的
双保险，不是矛盾。裁决里现在同时报两个数（`evidence.paired_delta`），读的人不用猜。

### 15.2 影子转正提案的判据（config `learning.shadow`）

```
在线真值天数 ≥ min_days(30)
且 按天自助 P( mean_d[ 影子前10超额_d − 正式前10超额_d ] > 0 ) ≥ p_better(0.90)
```

达标 → 发「[提案] 影子排序器转正」邮件、落 `state/shadow_proposal.json`，
之后每 `remind_days`(10) 天最多再提醒一次。切换动作永远人工：系统不写参数、
不动 score.py。`shadow.promotion_stat` 是这段统计，`selftest_learn.check_shadow_stat`
钉住五种情形（稳定领先 / 天数不足 / 五五开 / 完全相同 / 空）。

### 15.3 面板与状态
